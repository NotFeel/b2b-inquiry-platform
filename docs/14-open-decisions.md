# 14. 业务待确认事项与建议默认值

以下事项不阻塞建立项目骨架，但正式上线前应由业务负责人确认。没有确认时按“建议默认值”实施，并记录在配置中。

| 事项 | 建议默认值 | 原因/影响 |
|---|---|---|
| 站点主域名与品牌名称 | 先用环境配置占位 | 影响 canonical、邮件和分享链接 |
| 前台是否需要除英文外的语言 | 第一阶段只有 `en-US` | 后台双语与产品内容多语言是不同问题；模型先为多语言预留 |
| 商品尺寸单位 | L/W/H：cm | 后台输入与前台展示统一使用 cm；现有数据库仍以整数 mm 持久化，在表单与公共详情边界转换，禁止混用 |
| 箱规尺寸单位 | L/W/H：cm | 与箱规重量 kg 的包装场景匹配 |
| 商品重量 | g | 按需求；API 字段名必须包含单位或文档明确单位 |
| 商品内部价格 | CNY，NUMERIC | 产品价格仅后台使用；PI 报价币种独立 |
| 停产产品前台行为 | 默认不显示 | 若需要保留 SEO 历史页，需定义停产标签与替代品逻辑 |
| 批量询盘最大 SKU 数 | 20 | 控制 WhatsApp URL 长度并确保所有 SKU 都能写入消息 |
| WhatsApp 号码 | 全局单号码 | 多业务员分流可以后续加入按地区/产品分配规则 |
| WhatsApp 客户自动同步 | MVP 人工录入 | 自动收消息需要官方 Business Platform API/Webhook 和合规配置 |
| GeoIP 来源 | 优先可离线更新的 GeoIP 数据库；留 provider adapter | 降低外部服务依赖；准确率仅国家/地区级 |
| 实时访客窗口 | 最近 5 分钟有心跳 | 指标定义清楚，不把“实时”误解为精确在线人数 |
| 访问数据保留 | 原始事件 90 天、聚合数据 13 个月（可配置） | 初始运营默认值；需结合隐私和业务需要确认 |
| Excel/PDF 上传最大文件 | 10 MB 起步，按负载调整 | 大文件可能消耗 CPU/内存/临时磁盘 |
| Excel 模板定制方式 | 表头映射 + 命名占位符 | 兼顾多模板和维护性；模板启用前必须预检 |
| PI 币种/汇率 | 行价格由业务人员手动录入；汇率自动化暂不启用 | 防止错误报价；自动换算需明确汇率来源和生效时间 |
| 多业务员账号 | 每人独立后台账号 | 便于查询责任人和审计，不共享后台账号 |
| 文件物理删除策略 | 导出文件删除为硬删除；保留脱敏审计事件 | 满足业务要求同时保留安全追踪 |
| 首页商品分区来源（2026-10-17 确认） | `isFeatured` → 首页精选区；`isNew` → 首页新品区；`isPreOrder` → 首页预售区；三者均为运营勾选，互不替代 | 首页展示是运营决策，与商品生命周期、标签各自独立 |
| 商品标签与首页标记的关系（2026-10-17 确认） | 标签用于前台商品图片上的角标；`isFeatured`/`isNew`/`isPreOrder` 只决定是否进入对应首页分区。二者不冲突、**不做去重或互相同步** | 标签是可扩展的展示分类，首页标记是策划位；避免一套数据两个事实来源 |
| 首页预售区的生效条件（2026-10-17 确认） | 必须同时满足：`lifecycleStatus='preorder'` + `isPreOrder=true` + 已发布；生命周期离开预售时服务端自动清除 `isPreOrder` | 生命周期仍是业务事实；勾选框只是"是否上首页"的运营决策 |
| 隐私合规目标市场 | 上线前由业务/法务确认 | 涉及 Cookie、数据主体权利、分析工具和数据传输规则 |

## 上线前必确认项

1. 公司正式英文名、Logo、地址、联系方式、隐私/条款内容。
2. WhatsApp 目标号码及是否需要多个号码按地区分流。
3. 产品字段单位、价格币种、PI 的正式计算/审批规则。
4. 目标客户主要国家/地区和访问分析合规要求。
5. 生产托管位置、备份 RPO/RTO、文件存储成本上限。
