# B2B Inquiry Platform：手机端产品列表双列布局可执行优化方案

- 文档版本：v1.0
- 日期：2026-10-20
- 适用范围：前台产品目录页、分类商品页及其共用的产品卡片组件
- 目标：在手机端一行展示多件产品，默认采用双列网格，同时确保图片、标题、SKU、标签、详情入口和询盘按钮清晰完整。
- 实施原则：先核实现有页面组件与样式，再小步修改；保留现有查询、筛选、分页、询盘和多语言逻辑，不以纯 CSS 隐藏功能来换取视觉紧凑。

## 1. 结论与推荐方案

**可实现，推荐手机端默认一行两张产品卡片（2 列）。** 这适用于以图片浏览、目录筛选和批量询盘为主的 B2B 产品展示站。双列能提升首屏商品密度，减少用户连续滚动距离。

不建议所有设备都强制两列。推荐响应式规则：

| 可用内容宽度 | 推荐布局 | 说明 |
|---|---|---|
| 小于 340 CSS px | 1 列，或经真机验证后使用极紧凑 2 列 | 优先保证按钮、标题与触控空间；不要产生横向滚动 |
| 340–639 CSS px | 2 列 | 手机默认双列；卡片间距 10–12px |
| 640–899 CSS px | 2 或 3 列 | 根据容器实际宽度与卡片最小宽度决定 |
| 900–1199 CSS px | 3 列，必要时 4 列 | 取决于左侧分类栏是否占用空间 |
| 1200 CSS px 及以上 | 4 列或当前桌面布局 | 不改变既有桌面体验，除非验证后确认收益 |

断点是建议初值，不是不可变设计规范。应以**产品列表容器的实际可用宽度**而非仅依据设备名称来决定列数。若产品目录有固定宽度侧栏，手机端应将侧栏折叠为抽屉或筛选入口，不应让侧栏挤压双列卡片。

## 2. 当前页面观察与需要核实的点

从当前可读取的分类页内容可见，商品卡片包括：产品图片、Featured/New/Pre-order 徽标、产品名称、SKU 与复制操作、描述、分类/标签、`View details` 和 `Add to inquiry`。因此双列布局不能只处理图片网格，还必须处理信息密度与按钮布局。

当前仅能读取页面文本，不能从文本快照确认手机视口下的真实宽度、裁切位置、computed CSS 或浏览器溢出情况。实施前必须在开发者工具或真实设备上复现，确认：

1. 当前产品列表是否由 CSS Grid/Flex 实现，网格样式来自哪个组件/样式文件。
2. 手机断点下是否仍然单列，以及是否有固定宽度、`min-width`、固定高度或 `overflow: hidden` 导致挤压/裁切。
3. 分类页与产品目录页是否共用同一商品卡片组件；若共用，优先修复共用组件，避免页面间样式分叉。
4. `Add to inquiry` 的成功/已添加/禁用状态、详情跳转、SKU 复制、徽标和询盘数量逻辑必须保持原有行为。

## 3. 目标信息层级

手机端卡片应按以下顺序组织：

1. **图片区**：正方形或接近正方形的稳定容器；图片完整显示，优先 `object-fit: contain`，避免产品本身被裁切。
2. **徽标区**：Featured、New、Pre-order 等状态徽标允许换行；徽标过多时应折行，不可遮挡图片主体或覆盖按钮。
3. **标题区**：最多 2 行，超出时视觉截断；完整产品名称仍应存在于详情页、可访问名称或合适的提示方式中。
4. **SKU 区**：保留 SKU；复制图标按钮需有可访问名称和足够触控尺寸。长 SKU 可换行或省略显示，不能撑宽卡片。
5. **简要信息区**：手机双列默认隐藏非关键长描述，或最多显示 2 行；不得通过隐藏价格来实现紧凑（前台仍不显示价格）。
6. **操作区**：`View details` 与 `Add to inquiry` 均须完整可见。窄卡片中建议两个按钮纵向堆叠、各占满宽度；空间足够时才并排。

不要为了双列把所有内容强制塞进固定高度卡片。卡片可采用 `display:flex; flex-direction:column`，信息区自然增长，操作区在内容之后。若设计要求同一行卡片底部对齐，可以在行内使用伸缩布局，但不能造成文本覆盖或按钮不可见。

## 4. 推荐布局规则

### 4.1 产品列表容器

- 使用 CSS Grid 管理列数与间距。
- 手机端左右留白建议 12–16px，卡片间距 10–12px。
- 通过 `minmax(0, 1fr)` 避免 Grid 子项默认最小内容宽度造成横向溢出。
- 网格子项必须允许收缩：`min-width: 0`。
- 禁止用负 margin、固定像素宽度或绝对定位强行拼出双列。

参考实现（类名应按仓库现有命名调整）：

```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 20px;
}

@media (max-width: 1199px) {
  .product-grid {
    grid-template-columns: repeat(3, minmax(0, 1fr));
    gap: 16px;
  }
}

@media (max-width: 899px) {
  .product-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
    gap: 12px;
  }
}

@media (max-width: 339px) {
  .product-grid {
    grid-template-columns: minmax(0, 1fr);
    gap: 12px;
  }
}

.product-card {
  min-width: 0;
  display: flex;
  flex-direction: column;
  height: 100%;
}
```

以上为建议起点。若现有桌面布局的列数、容器或断点不同，应结合当前项目的 CSS 体系整合，不要复制粘贴形成互相覆盖的媒体查询。

### 4.2 图片容器

```css
.product-card__media {
  width: 100%;
  aspect-ratio: 1 / 1;
  overflow: hidden;
  display: grid;
  place-items: center;
  border-radius: 14px;
}

.product-card__media img {
  display: block;
  width: 100%;
  height: 100%;
  object-fit: contain;
}
```

- 产品主体不应因 `object-fit: cover` 被切掉；只有确认素材是统一构图且业务接受裁切时，才使用 `cover`。
- 设置图片容器固定宽高比，避免图片加载前后卡片跳动。
- 如果图片有统一的内边距/背景，应在容器层处理，不要通过扩大图片尺寸压到文字或按钮区域。
- 图片应有适当 `alt`；装饰性图像才可使用空 alt。

### 4.3 标题、SKU 与徽标

```css
.product-card__title {
  min-width: 0;
  display: -webkit-box;
  -webkit-box-orient: vertical;
  -webkit-line-clamp: 2;
  overflow: hidden;
  overflow-wrap: anywhere;
}

.product-card__sku {
  min-width: 0;
  overflow-wrap: anywhere;
}

.product-card__badges {
  display: flex;
  flex-wrap: wrap;
  gap: 4px;
  min-width: 0;
}
```

- 标题 2 行截断仅限卡片摘要，不得截断实际数据或导致详情页丢失名称。
- SKU 复制按钮应 `flex: 0 0 auto`，文本区域 `min-width: 0`；复制按钮不应被压缩成不可点击的小点。
- 徽标可换行；不要通过 `white-space: nowrap` 让多个徽标撑破卡片。
- 手机端可减少冗长描述的展示，但必须保留辨识产品所需的信息。

### 4.4 操作按钮：优先纵向堆叠

双列卡片在常见手机上宽度有限。建议默认按钮纵向排列，优先保证主操作完整：

```css
.product-card__actions {
  display: flex;
  flex-direction: column;
  gap: 8px;
  margin-top: auto;
  min-width: 0;
}

.product-card__actions a,
.product-card__actions button {
  width: 100%;
  min-width: 0;
  min-height: 44px;
  box-sizing: border-box;
  white-space: normal;
  overflow-wrap: anywhere;
}
```

- `View details` 保留为详情链接；`Add to inquiry` 保留为真实按钮，不得将两个按钮嵌套在同一个链接里。
- 44px 是建议的最小触控高度；若项目设计系统对移动端有更严格标准，遵循更严格标准。
- 若翻译后的按钮文字较长，允许两行文字并增加按钮高度，不得裁切文本。
- 只有在实测卡片宽度足够、英文与中文标签都能完整展示时，才考虑将两个操作并排；不要以桌面截图判断手机效果。
- Loading、已添加、库存/状态限制等按钮状态也必须有完整可读的文字和可见反馈。

## 5. 分类页与目录页的配套处理

1. 分类导航侧栏在手机端收起为“Categories/分类”入口或抽屉；不应与商品网格长期并排占宽。
2. 搜索、排序、筛选可采用顶部紧凑工具条；筛选面板使用抽屉或折叠区，关闭后保留已选条件。
3. 已选分类、标签、搜索词和排序应保留在 URL/页面状态中，双列 CSS 改造不得破坏过滤逻辑。
4. 产品总数、空结果提示和分页放在网格之后；分页按钮需可触控，避免页码横向溢出。窄屏可使用 Previous / Page X of Y / Next 的紧凑布局。
5. 网格列数变化不应改变 API 分页总数、页码语义或排序稳定性。每页数量是否调整（例如从 12 个起）应由产品体验与 API 成本共同决定，不要把“每行两列”和“每页数量”混为一项改动。

## 6. 实施步骤（必须按顺序）

### P0：复现与定位

- 找到产品目录页、分类页共用的商品列表与产品卡片组件。
- 查找并记录现有 CSS/样式模块中的 `grid-template-columns`、`display:flex`、`min-width`、固定 `height`、`overflow`、`position:absolute` 和相关媒体查询。
- 在开发者工具中测试 320、360、375、390、430 CSS px 宽度；记录实际列数、卡片宽度、按钮是否完整、是否有横向滚动。
- 确认现有产品图片、徽标、SKU、标签、详情链接、加入询盘按钮的 DOM 结构与状态逻辑。

### P1：实现响应式双列

- 在共享商品网格组件中调整列数与间距。
- 处理分类侧栏在手机端的收起/抽屉逻辑（如果当前布局存在侧栏占宽问题）。
- 统一图片容器比例和 `object-fit`。
- 修正卡片子项 `min-width: 0`、标题换行、SKU 复制区与徽标折行。
- 手机端按钮改为纵向堆叠并满足最小触控高度。
- 不改变询盘业务逻辑、产品 URL、筛选参数和权限行为。

### P2：细节与性能

- 检查图片尺寸、懒加载与加载占位，避免网格滚动时大幅布局跳动。
- 为卡片 hover/focus/active/disabled/loading 提供一致样式；触屏端不依赖 hover 才能操作。
- 确认浅色马卡龙配色下按钮文字对比度足够，不能只靠背景颜色区分状态。
- 检查英文长词、中文文本、超长 SKU、3 个以上徽标和无描述产品。

## 7. 验收测试矩阵

| 场景 | 视口/数据 | 验收标准 |
|---|---|---|
| 小屏手机 | 320px | 无横向滚动；默认允许退回单列以保证可用性；按钮不裁切 |
| 常见手机 | 360/375/390px | 默认两列；卡片内容在边界内；图片比例一致 |
| 大屏手机 | 430px | 两列间距合理，不出现过度拉伸的空白 |
| 平板 | 768px | 网格列数与侧栏/筛选布局协调，无挤压 |
| 桌面 | 1280px、1440px | 原有桌面体验保持，网格无意外变成两列 |
| 长标题 | 英文长词/中文标题 | 最多两行摘要；卡片不被撑宽；详情入口可用 |
| 多徽标 | Featured + New + Pre-order | 徽标允许折行，不遮挡图片和操作区 |
| SKU | 超长 SKU | 可读或合理省略；复制按钮仍可操作 |
| 按钮 | 默认、loading、已添加、禁用 | 文案完整、触控区域足够、状态正确 |
| 交互 | 点击详情/加入询盘/复制 SKU | 行为与改造前一致，无事件冲突或嵌套交互问题 |
| 多语言 | en-US、zh-CN | 两种语言下按钮均不裁切，不出现水平滚动 |
| 页面覆盖 | 产品目录、分类详情 | 两个页面布局一致且没有组件样式回归 |
| 分页筛选 | 搜索、分类、标签、排序、翻页 | 状态与 URL 正确，网格列数变化不影响数据结果 |

## 8. 自动化/人工检查建议

- 若项目已有 Playwright/Cypress，增加手机视口回归用例；不要为此引入新测试框架，除非项目确实没有现成方案且团队同意。
- 自动检查 `document.documentElement.scrollWidth <= window.innerWidth`，并对每张卡片检查主要按钮是否落在卡片边界内。
- 通过 bounding box 检查按钮宽高和是否与相邻元素重叠；注意仅检查可见性不足以发现文字裁切。
- 至少一次在真实 iOS Safari 或 Android Chrome 上验证触控、滚动与按钮状态；桌面浏览器设备模拟不能完全替代真机。
- 对产品卡片截图做视觉回归，覆盖英文和中文、长短标题、徽标数量不同的商品。

## 9. 交付要求

完成后提交：

1. 修改文件清单（页面、共享卡片、样式、测试）。
2. 改动说明：断点、每个断点列数、卡片最小宽度、图片比例、按钮布局。
3. 执行的 lint/typecheck/test/build 命令及实际结果；未执行的明确标注。
4. 测试视口截图或记录，至少包含 320px、375px、430px、768px 和桌面宽度。
5. 已知限制与后续事项。

## 10. 验收定义

只有同时满足以下条件才算完成：

- 常见手机宽度下默认每行两件产品；极窄视口可以合理退回单列。
- 图片完整、比例稳定，商品卡片之间没有明显高度/间距异常。
- 标题、SKU、徽标不会把卡片撑出屏幕；操作按钮完整可见且可点击。
- 页面没有横向滚动条或元素相互覆盖。
- 产品详情、加入询盘、复制 SKU、筛选、分页和多语言行为保持正常。
- 桌面与平板布局未发生未经设计的回归。
- 测试结果真实记录，不能仅凭代码修改宣称验收通过。
