# 07. 后端技术标准（NestJS API）

## 1. 分层职责

- Controller：路由、HTTP 状态、DTO 入参/出参；不放业务流程和 SQL 细节。
- Service / Use Case：业务规则、事务边界、权限前置条件与任务编排。
- Repository / Prisma：数据查询与持久化；避免 Controller 直接调用 ORM。
- DTO / Schema：请求校验和输出字段白名单；公共 DTO 与管理 DTO 分离。
- Guard：身份验证与权限检查；Interceptor：requestId、响应处理/日志；Filter：统一异常映射。
- Worker：长耗时任务；API 负责排队、权限和状态查询。

## 2. 模块组织

每个 NestJS 业务模块原则上包含 `module.ts`、`controller.ts`、`service.ts`、`dto/`、`policy/`、必要的 `repository` 与测试。模块之间通过服务接口或事件协作，不互相访问其他模块的私有 ORM 细节。

## 3. 校验与错误

- 所有外部输入进行类型、长度、枚举、范围和业务关系校验。
- 禁止信任客户端传入的 `createdBy`、`updatedBy`、角色权限、文件存储 key、合计金额或产品发布权限。
- 统一错误码，例如 `AUTH_INVALID_CREDENTIALS`、`FORBIDDEN`、`CATEGORY_CYCLE_DETECTED`、`PRODUCT_SKU_CONFLICT`、`UPLOAD_TYPE_NOT_ALLOWED`、`JOB_FAILED`。
- 对客户电话、邮箱等做长度限制及规范化；对于富文本描述使用服务端 HTML sanitizer 和安全白名单。

## 4. 认证与权限

- 无自助注册 API；初始化账号只通过安全脚本或运维流程。
- 密码用当前推荐的密码哈希算法及安全参数存储，优先 Argon2id；绝不自行设计加密算法。
- 登录端点进行账号/IP 限流、统一错误文案、防用户枚举；密码不写日志。
- 使用 HttpOnly、Secure、SameSite Cookie；状态变更请求做 CSRF 防护；全站 HTTPS。
- 每个管理 API 均使用认证 Guard + 权限 Guard；默认拒绝。列表、查看、更新、删除、导出和下载应有独立权限代码。
- RBAC 授权变更应审计；防止移除系统最后一名管理员或把超级管理员权限授予未授权角色。

## 5. 数据一致性

- 多表更新使用事务；事务保持短小，不包含慢速文件上传、下载或 Excel 生成。
- SKU、用户名、电话号码、PI 编号等唯一性最终由数据库唯一约束兜底。
- 处理同一商品的并发更新时采用乐观锁/updatedAt 检查或明确最后写入规则。
- 删除对象存储文件与数据库记录不能假设具有原子性；使用状态机、Outbox 或重试任务协调。
- 所有日期使用 UTC；价格、PI 行金额用 Decimal；数量字段区分整数和精度允许的小数。

## 6. 查询和性能

- 公共产品查询使用字段投影，不返回完整 ORM 实体。
- 避免 N+1；分页必须在数据库执行；过滤与排序列建立合理索引。
- 对品类树遍历设置最大节点数/深度保护，避免恶意构造深树造成资源消耗。
- 对搜索输入长度、页大小、请求体大小、导出数据量、任务并发、转换时间设置限制。
- 用 explain/analyze 诊断慢查询；索引变更先在类生产数据量上测量。

## 7. 文件与后台任务

- 使用随机文件 key，不用原始文件名做物理存储路径；原始名称仅作为安全转义后的显示元数据。
- 上传文件先进入 quarantine / 临时区；校验、扫描、解析成功后再标记可用。
- 队列任务必须幂等，有超时、重试上限、死信/失败记录和人工重试入口。
- 不把大 Excel、PDF 二进制塞进数据库；数据库存对象 key、哈希、大小与状态。
- 下载使用权限检查后的短时 signed URL 或 API 流式代理，禁止公开静态可猜路径。

## 8. 可观测性

- 每个请求有 `requestId`；每个异步任务有 `jobId`；日志按 JSON 记录时间、级别、模块、耗时与错误码。
- 指标覆盖 API 请求率、错误率、P95 延迟、DB 连接池、Redis 队列积压、失败
  任务、磁盘/对象存储错误和 Excel 导出耗时。
- 健康检查分 liveness 与 readiness；readiness 检查关键依赖但必须设置超时，避免健康检查本身拖垮服务。
- 告警不要包含密码、Session、客户完整电话、原始 IP 或文件内容。

## 9. 测试要求

- Service 单元测试验证业务规则；Controller 集成测试验证校验、认证和权限；E2E 测试覆盖完整流程。
- 必测：未授权访问拒绝、越权操作拒绝、公共价格字段不存在、重复 SKU/电话并发冲突、导出删除重试、文件上传拒绝策略、金额精度。
