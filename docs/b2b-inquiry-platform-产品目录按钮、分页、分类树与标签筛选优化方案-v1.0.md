# B2B Inquiry Platform：产品目录按钮、分页、分类树与标签筛选优化方案

- 文档版本：v1.0
- 日期：2026-10-20
- 目标页面：`http://localhost:3000/en-US/products?category=demo-fasteners`
- UI 方向：年轻、轻量、可爱的小店风格；马卡龙配色；以产品展示与 WhatsApp 询盘为核心，不显示产品价格
- 状态：可执行设计与开发任务清单；实施前仍需核对当前页面源码、API、测试与路由实现

## 1. 目标与范围

本次优化只针对产品目录页及其直接相关的筛选、分类、标签、分页和产品卡片交互。目标是：

1. 让搜索、筛选、排序、清除条件、查看详情、加入询盘等按钮有明确主次和一致反馈。
2. 分类树递归展示到真实数据的最末级，不限制固定层数；展开节点与筛选节点分开操作。
3. 标签筛选展示全部有效标签；明确区分运营标签（如 `New`、`Featured`）与业务状态（如 `Pre-order`）。
4. 实现可理解、可访问、URL 可分享的分页；筛选、排序、分页互相协调。
5. 统一采用马卡龙色彩与圆润但不过度幼稚的组件样式，保持小店/工厂产品目录气质。
6. 不破坏现有多语言、品类 ID 关联、产品 SKU、批量询盘和 WhatsApp 询盘流程。

## 2. 当前页面可见问题与核验边界

根据当前已读取的产品目录页面文本：

- 页面存在顶部搜索和目录内搜索；需要核实二者是否重复、是否各自承担不同设备场景。建议保留一个主搜索入口，避免桌面端重复表单。
- 分类筛选当前显示为简单链接列表，不能明显表达父子层级；示例中出现 `Industrial components (demo)`、`Fasteners (demo)`、`Toys`、`stress relief toys`，但没有清楚显示完整祖先路径和多级展开关系。
- 筛选区当前可见 `Pre-order`，产品卡片上又出现 `Featured`、`New`、`Pre-order` 等标签，说明筛选项来源与卡片标记可能不一致，必须核对标签 API、产品布尔字段和字典状态的来源。
- 页面存在排序选择和 `Apply filters` 按钮；需要确认排序是否立即生效、筛选是否必须手动提交，以及移动端筛选抽屉是否共享同一份状态。
- 产品卡片包含 `View details`、`Add`、复制 SKU 等动作；需建立主次层级、加载/成功/失败状态和触屏尺寸。
- 当前读取的页面文本未显示分页控件；应检查分页是否未实现、被条件隐藏，或因数据量较少而未达到分页阈值。

上述是页面文本能支持的观察，不等于已经定位源码根因。修复前应在浏览器和代码中复现并核对。

## 3. 马卡龙视觉规范

### 3.1 色彩 token

| Token | 色值 | 用途 |
|---|---|---|
| `--color-page` | `#FFF9F3` | 页面奶油白背景 |
| `--color-surface` | `#FFFFFF` | 产品卡片、筛选面板 |
| `--color-pink` | `#F7C6D9` | 轻强调、选中装饰、次要标签 |
| `--color-pink-soft` | `#FCE7EF` | 粉色浅底、hover 背景 |
| `--color-mint` | `#CDEFE1` | 已选筛选、轻成功状态 |
| `--color-butter` | `#FFE5A3` | 新品等提示性徽标的浅底 |
| `--color-lavender` | `#DCD7FF` | 精选/内容型徽标浅底 |
| `--color-sky` | `#CDE8FA` | 信息型状态与次级强调 |
| `--color-ink` | `#433B49` | 主文本；必须保持足够对比度 |
| `--color-muted` | `#746B79` | 次级说明文字；需验证对比度 |
| `--color-border` | `#E9DFE8` | 边框、分割线 |
| `--color-primary` | `#7455A6` | 主要按钮、键盘焦点；与白色文字需做对比度测试 |
| `--color-primary-hover` | `#60428F` | 主按钮 hover |
| `--color-danger` | `#B83F5A` | 删除、清空等危险动作的文字/边框 |

注意：粉、薄荷、黄、紫等浅色适合作为背景，不应直接用浅色文字放在白底上。正文和按钮文字应使用高对比深色。最终以 WCAG 对比度测试结果为准。

### 3.2 形状、间距和动效

- 页面最大内容宽度建议 `1280px`，两侧留白随视口变化。
- 卡片圆角 `16–20px`；输入框与按钮 `12–14px`；筛选 chip 使用圆角胶囊。
- 控件最小触控高度建议 `44px`；按钮文字不因宽度不足而裁切。
- 阴影轻柔、边框低对比，不使用大面积高饱和渐变。
- hover 只使用轻微颜色变化、边框变化或 `1–2px` 位移；遵循 `prefers-reduced-motion`。
- 不要给所有组件都加不同颜色；马卡龙颜色用于层级和状态提示，页面主体保持干净。

## 4. 页面布局建议

### 4.1 桌面端（≥1024px）

```text
Header / 主导航 / Inquiry list

Breadcrumb: Home / Products / Fasteners
标题：Product catalogue                 产品数量：xx items
说明：Browse products and build one WhatsApp inquiry.

[搜索产品名称或 SKU____________________] [Search]

┌───────────────┐  ┌─────────────────────────────────────────────┐
│ Categories    │  │ Active filters: [Fasteners ×] [New ×] [Clear]│
│ 树形分类       │  │ Sort by [Recommended ▼]  View [Grid/List]    │
│               │  ├─────────────────────────────────────────────┤
│ Tags          │  │ 产品卡片网格（桌面 3–4 列，按实际宽度）       │
│ [New]         │  │                                             │
│ [Featured]    │  │ 图片 / 徽标 / 标题 / SKU / 简述 / 操作        │
│ [Pre-order]   │  │                                             │
│ [其他有效标签] │  └─────────────────────────────────────────────┘
└───────────────┘

                         [Previous] 1 2 3 … N [Next]
```

- 左侧筛选栏可粘性定位，但不得遮挡页脚或窄视口内容。
- 桌面端筛选条件变更后应有明确应用策略：推荐即时更新；若因性能必须手动应用，则把未应用状态与已应用状态区分清楚。
- 不要同时保留两个视觉同等重要的搜索框。

### 4.2 平板端（768–1023px）

- 分类/标签改为可打开的筛选抽屉或顶部筛选面板。
- 搜索框占满可用宽度；排序独立一行或与筛选按钮并排。
- 产品网格建议 2 列，卡片操作避免挤压。

### 4.3 手机端（≤767px）

- 搜索框一行，搜索按钮可采用图标+文字或清晰的图标按钮，但必须有可访问名称。
- 筛选按钮打开底部抽屉/侧边抽屉；抽屉内分类、标签、排序共用同一状态。
- 筛选抽屉底部固定显示 `Reset` 与 `Show N products`，关闭抽屉时不能意外丢失已应用条件。
- 产品卡片单列或两列按可读性决定；SKU、标题、标签与加入询盘按钮不能被裁切。
- 分页在手机端用 `Previous`、`Page X of N`、`Next`，可选页码过多时不强制横向铺开全部数字。
- 批量询盘入口若固定在底部，必须预留内容 padding，不能覆盖分页、卡片按钮或页脚。

## 5. 按钮和交互规范

### 5.1 按钮层级

| 类型 | 用途 | 样式建议 | 行为要求 |
|---|---|---|---|
| Primary | Search、Add to inquiry、Show products | 紫色主色底、深对比文字/白字（先做对比度测试） | 有 loading、成功反馈、防止重复提交 |
| Secondary | View details、Filters、Sort | 白/奶油底、浅紫边框、深色文字 | hover/focus 状态明确 |
| Tertiary/Ghost | Copy SKU、关闭抽屉、次要操作 | 透明底，hover 使用浅马卡龙底 | 图标按钮必须有 `aria-label` 与 tooltip |
| Filter chip | 已选分类/标签 | 对应浅色底、深色文字，带可见移除符号 | 删除单个条件后立即更新 URL 与结果 |
| Destructive | 清除全部（如会丢弃表单外状态）或删除操作 | 低频使用红色文字/边框 | 需要确认的操作才弹确认框，不把普通清筛选设计成危险红色大按钮 |

### 5.2 具体按钮规则

- `Search`：按 Enter 可提交；请求期间禁用重复提交；失败显示可理解的错误，不清空搜索词。
- `Filters`：显示当前已选条件数量，如 `Filters (3)`；数量需由真实筛选状态计算。
- `Apply filters`：如果改为即时筛选则移除该按钮；如果保留手动应用，则只提交抽屉内草稿状态，并在关闭/重开时定义清楚行为。不要出现“按钮可点但结果不变”的假操作。
- `Clear filters`：清除分类、标签、搜索、排序和页码中哪些状态必须定义清楚。建议提供 `Clear all` 清除所有筛选条件并回到第 1 页，但保留默认排序；如果保留搜索词，则按钮文案应改成 `Clear filters` 并明确只清筛选项。
- `View details`：整个卡片标题/主视觉可以链接详情页；按钮仅作为辅助，避免整卡链接内嵌按钮导致交互冲突。
- `Add to inquiry`：卡片上使用明确文案，不只写 `Add`；添加成功显示 `Added` 或 toast，重复添加应按项目询价清单规则更新数量/状态，而不是悄悄新增重复项。
- `Copy SKU`：复制成功提示 `SKU copied`；失败提示可手动复制。按钮不能抢占主 CTA 视觉。
- 所有按钮在 hover、focus-visible、active、disabled、loading 状态下均有可见变化。

## 6. 多级分类树：递归显示到最末级

### 6.1 数据与渲染规则

项目基线明确：`Category` 使用 `parentId` 形成树，支持多级；不应固定写死两层或三层。`schema.prisma` 中可见 `Category.id` 为 UUID、`parentId` 为可空 UUID、`children` 自关联、`sortOrder`、`enabled`、`visible`，翻译由 `CategoryTranslation` 提供。因此应以 API 返回的真实树为准，递归渲染全部层级。

实现要求：

1. 递归构建 `CategoryNode`，按 `sortOrder ASC` 排序；同序时使用稳定的名称/ID 作为次序，确保刷新后顺序稳定。
2. 节点层级由 `parentId` 关系决定，不在 UI 中假设只有 `parent -> child` 两层。
3. 每个有子节点的分类显示独立展开/折叠按钮；点击展开图标只展开，不触发筛选。
4. 点击名称/复选框才选择筛选条件；展开和选择事件必须分离。
5. 当前选择显示完整路径，例如 `Toys / Stress Relief Toys / Fruit Squishies / Strawberry`。
6. 如果业务允许父分类筛选，则选择父分类默认包含其全部后代商品；不应强制只选叶子节点。若实际 API 当前只筛选直接关联商品，需要修复服务端后代查询并统一商品数口径。
7. 节点数量应明确含义：建议显示“该分类及后代的可展示商品数”，与点击后实际结果一致；如果显示直接关联商品数，需用不同标签说明。
8. 搜索分类时自动展开匹配节点的祖先，并高亮命中名称；清空搜索后恢复用户此前展开状态。
9. 树节点支持键盘导航、`aria-expanded`、可见焦点、足够触控区域。
10. 隐藏/禁用分类不应被公开筛选返回；但后台维护的隐藏分类与公开分类必须遵循同一服务端规则。

### 6.2 选择与 URL 状态

- 前台 URL 使用稳定 slug（例如 `?category=demo-fasteners`）还是 ID，沿用现有路由契约；不要为了 UI 改动随意变更 URL 形式。
- 页面首次加载应从 URL 恢复筛选状态。
- 选择/取消分类后更新 URL，浏览器前进/后退可以恢复状态。
- 分类筛选、标签筛选、搜索、排序变化后，页码重置为第 1 页。
- 需要验证选中分类是否仍启用、是否可公开；非法或失效的 URL 参数要回退到安全默认状态并给出合理反馈。

### 6.3 分类树验收

- [ ] 任意深度的分类均可展开并显示到叶子节点。
- [ ] 只有叶子节点、只有父节点、空子节点和深层分支都正常。
- [ ] 展开箭头不会意外触发筛选；选择节点不会意外折叠。
- [ ] 选择父节点时，结果与产品数量口径一致地包含/不包含后代。
- [ ] 搜索深层分类时可看到祖先路径并可选择。
- [ ] 刷新页面、复制 URL、浏览器前进后退后筛选状态正确。
- [ ] 分类排序、locale 翻译、禁用/隐藏分类行为正确。

## 7. 标签与产品状态：必须统一来源，但不能混淆语义

### 7.1 现有模型需要核验的关键点

`schema.prisma` 当前可见：

- `Product.isNew` 与 `Product.isFeatured` 是独立布尔字段。
- `Product.lifecycleStatus` 为生命周期状态；另有 `isPreOrder` 作为首页预售内容精选标记，注释明确其含义与生命周期不同。
- `Tag` 有稳定 `code`、`enabled`、`colorToken`；`TagTranslation` 保存 locale 对应 `label`；`ProductTag` 关联商品与标签。

所以 `New`、`Featured` 可能是产品布尔字段产生的徽标，不一定是 `Tag` 表中的标签；`Pre-order` 可能是生命周期状态，而不一定是运营标签。前台必须把它们分成不同筛选组，或通过明确的映射规则统一呈现，不能把数据来源混为一谈。

### 7.2 推荐筛选分组

**Product status / Highlights（系统属性）**
- New arrivals → `isNew = true`
- Featured → `isFeatured = true`
- Pre-order → 使用当前业务定义的生命周期状态筛选（核对 enum 与 service），不要错误地用首页 `isPreOrder` 精选标记代替生命周期状态

**Tags（运营标签）**
- 从 `Tag` 与 `TagTranslation` 获取全部 `enabled = true` 且适用于前台的标签。
- 每个标签使用稳定 `code` 或 ID 作为查询值，当前 locale 的 `label` 仅用于显示。
- 只展示实际有公开商品关联的标签，或将无商品标签显示为 disabled 并标注 0；不要出现点击后永远返回空结果的筛选项。
- 标签按 `sortOrder`（如果模型/API 有）或项目定义的稳定顺序展示；如果模型没有排序字段，先确认是否需要最小迁移，不要在前端按翻译后的字符串随意排序而导致中英文顺序不一致。
- 标签较多时先展示前 N 个并提供 `Show all / Show less`，或在标签区提供搜索；“全部”必须能访问，不得截断后无法展开。

### 7.3 统一标签渲染与查询

- 后台维护的标签名称、code、启用状态与商品关联是前台筛选的真实来源。
- 产品卡片徽标可以来自 `isNew`、`isFeatured`、生命周期状态和运营标签，但视觉上应有一致的 chip 组件，并且每种徽标有明确语义。
- `New`、`Featured`、`Pre-order` 在卡片出现，并不自动意味着它们都属于 Tag 关系表；筛选 UI 应在代码层明确区分系统属性与运营标签。
- 如果产品确实关联多个 `Tag`，公开 API 应返回完整且已翻译的标签列表，不应只返回第一个标签或固定白名单。
- 标签筛选建议支持单选/多选，首期若采用单选，必须明确 UI 与 API 规则；若多选，明确是 AND 还是 OR。推荐同组运营标签采用 OR，跨组条件（分类 + 标签 + 状态）采用 AND，并在界面显示已选 chip。
- 标签条件变更后页码回到第 1 页，URL 可复制分享。

### 7.4 标签验收

- [ ] 已启用的前台标签均能展示，超出首屏时可展开全部。
- [ ] `zh-CN` 与 `en-US` 标签名称正确，不用显示名称作为查询主键。
- [ ] `New`、`Featured`、`Pre-order` 各自对应正确字段/状态规则。
- [ ] 禁用标签不出现在前台；无关联商品的标签按定义隐藏或禁用。
- [ ] 多选规则、清除单个标签和清除全部行为一致。
- [ ] 产品卡片徽标与筛选结果一致，不出现卡片标记和筛选语义冲突。

## 8. 分页设计与行为

### 8.1 分页 UI

桌面端：

`Showing 1–12 of 58 products`　`[Previous] [1] [2] [3] […] [5] [Next]`

手机端：

`[Previous]　Page 2 of 5　[Next]`

要求：
- 每页默认数量建议 12（最终以现有 API 性能与产品卡片密度核验）；可选 12/24/48 时需要服务端有上限。
- 显示当前范围和总结果数，避免用户不知道筛选后还有多少产品。
- 当前页码视觉突出，但不可只靠颜色表达；当前页添加 `aria-current="page"`。
- 首页 Previous 禁用；末页 Next 禁用；按钮 disabled 状态清晰且不能触发请求。
- 页码较多时显示首尾页和当前附近页，使用省略号，不渲染数百个按钮。
- 加载下一页时保留布局并显示忙碌状态；失败时保留原结果和页码，可重试。
- 如果切换筛选后总页数变少，自动回到第 1 页，避免停留在空的旧页码。

### 8.2 URL 与查询一致性

建议 URL 示例（参数名应沿用现有实现）：

`/en-US/products?category=demo-fasteners&tag=new&page=2&limit=12&sort=newest`

- URL 是筛选/分页状态的可恢复来源；刷新、复制链接、浏览器前进/后退均恢复相同结果。
- 所有筛选、搜索和排序变化重置 `page=1`。
- 查询参数需校验：页码为正整数、每页数量在允许范围内、排序值为白名单值。
- 分类、标签、排序和分页的总数统计必须使用相同过滤条件；不要出现列表有 12 条但总数来自未筛选数据的情况。
- 服务端应返回 `items`、`total`、`page`、`pageSize`、`totalPages` 或现有统一分页结构；前端不应仅通过当前页长度猜总数。
- 产品列表排序要有稳定次级排序字段（例如 `sortOrder` 后接 `id`），避免翻页时商品重复或遗漏。
- 如果项目采用 cursor pagination，继续沿用当前接口契约，本文页码示例仅作为交互语义，不要求强制改成 offset pagination。

### 8.3 分页验收

- [ ] 多页结果能前进、后退、直接跳页。
- [ ] 第一页/末页边界按钮状态正确。
- [ ] 搜索、分类、标签、排序变化后重置到第一页。
- [ ] 浏览器刷新与前进/后退保持状态。
- [ ] 总数、范围、总页数来自同一筛选条件。
- [ ] 数据总数不足一页时按设计隐藏分页或显示单页状态，不渲染无效按钮。
- [ ] 空结果显示友好空状态、清除筛选入口，不显示错误页码。

## 9. 产品卡片优化

卡片信息优先级建议：

1. 主图（固定比例，建议 4:3 或按现有图片资产确定）。
2. 顶部徽标：最多显示 2–3 个，超出后收纳为 `+N` 或放详情页，避免标签堆叠。
3. 产品名称（最多 2 行，完整文本仍可访问）。
4. SKU 与复制按钮。
5. 一段短描述（移动端可缩短）。
6. 分类/关键标签（避免重复显示同一状态）。
7. `View details` 次按钮 + `Add to inquiry` 主按钮。

具体要求：
- 不显示价格，继续遵守项目定位。
- 产品图统一尺寸、`object-fit` 和占位图；图片加载失败不影响卡片布局。
- CTA 文案用 `Add to inquiry`，避免只有 `Add` 不清楚操作含义。
- 已添加状态要能从询价清单状态回显；同一产品重复添加按现有询价逻辑更新，而非产生意外重复行。
- 卡片内链接与按钮不能形成嵌套交互元素；键盘 Tab 顺序合理。
- 长 SKU、长英文名和窄屏布局不溢出。

## 10. 状态与异常处理

| 场景 | 预期行为 |
|---|---|
| 搜索无结果 | 显示 `No products found`、当前搜索词和清除条件入口 |
| 分类无商品 | 显示该分类暂无可展示产品，不伪造数量 |
| 标签筛选无商品 | 提示无匹配商品，并允许移除标签 |
| 标签 API 失败 | 显示可重试错误，不把失败误显示为“没有标签” |
| 分类树 API 失败 | 保留页面其他部分并显示分类加载失败与重试入口 |
| 产品列表加载失败 | 保留筛选状态，显示重试；不误报 0 个商品 |
| 页码超出总页数 | 回到有效页码或显示明确的无效页处理，不无限加载 |
| 图片加载失败 | 统一占位图和可访问的替代文本 |
| 添加询盘失败 | 保留当前页面/筛选条件，提示原因并可重试 |
| URL 参数非法 | 忽略非法值或重定向到安全默认值，避免服务端异常 |
| 英文翻译缺失 | 使用项目定义的明确 fallback/缺失提示，不把内部 code 暴露给用户 |

## 12. 代码修改边界与实施原则

- 优先复用现有组件和 API，不另建第二套筛选状态管理。
- 共享 `CategoryPicker` 若目前主要用于后台商品管理，可抽取可复用的树形数据/节点逻辑，但前台交互样式与选择规则应由产品目录场景明确配置，不能直接套用后台复杂表单。
- `Category.id` 是 UUID，`parentId` 表示树关系；商品通过 `categoryId` 关联。筛选用 slug/ID 的具体 URL 契约沿用现有实现，服务端查询最终必须映射到真实 ID。
- 标签翻译使用稳定 `code`/ID 做查询，显示名称使用当前 locale。不要使用显示 label 作为数据库查询键。
- 不把 `isPreOrder`（首页精选标记）误当作 `lifecycleStatus`（生命周期状态）。
- 不因 UI 美化而改变价格隐藏、产品发布状态、询盘清单和 WhatsApp 消息结构。
- API、服务端输入校验、权限（如公开接口的发布过滤）、数据库约束和审计要随改动一起核验。
- 本任务原则上不需要新建数据表；如果确实需要标签排序字段或 API 结构变更，先说明差异和迁移理由，再执行最小迁移。
