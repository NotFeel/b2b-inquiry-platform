# 06. 前台/后台页面开发与统一 UI 标准

## 1. 视觉目标

- 前台：简洁、可信、适合海外 B2B 采购；重点突出产品图片、品类路径、规格和 WhatsApp CTA；避免零售结算式购物体验。
- 后台：信息密度较高但层级清楚，表格和批量操作优先；重要删除/发布操作必须有确认与反馈。
- 一套设计 Token 管控颜色、间距、字号、圆角、阴影、断点与层级。页面不得自行创建近似但不一致的色值。

## 2. 响应式断点建议

- Mobile：360–767 px；单列布局，侧栏转抽屉，表格改卡片或横向滚动容器，触控目标至少 44×44 CSS px。
- Tablet：768–1023 px；可折叠侧栏，商品列表 2–3 列，过滤器可抽屉化。
- Desktop：1024 px 及以上；后台可用侧栏 + 主内容，前台产品栅格 3–4 列（依据容器宽度调整）。
- 使用 CSS Grid/Flex 与流式容器；禁止对整页设置固定宽度。任何主要页面在 360px 下不得出现非预期横向滚动。

## 4. 前台页面规范（英文）

### 首页
- 顶部：Logo、品类/导航、全局搜索、询盘清单入口（仅代表选品列表，不显示结算金额）。
- 内容：Hero 广告、主要品类入口、Featured Products、New Arrivals、Pre-order Products、公司能力/CTA、FAQ/Contact 链接。
- 产品卡片：统一图片比例、英文名称、SKU（可配置）、标签（Featured/New/Pre-order 等）、详情链接；任何位置不显示价格或“From $...”等价格暗示。

### 产品列表
- 桌面可左侧品类树 + 右侧列表；移动端品类筛选使用 Drawer。
- 显示总数、排序、分页和空状态；筛选条件可清除；页码/筛选需同步到 URL Query，方便分享和 SEO。
- 搜索支持 SKU、英文名称和经批准的描述字段；输入做长度限制和防滥用处理。

### 产品详情
- 图库支持主图切换、缩放或清晰大图；图片有 alt 文本。
- 显示 SKU、规格、重量、包装、箱规、标签、描述、所属品类与面包屑。
- WhatsApp CTA 清晰可见；移动端可用底部粘性按钮，但不得遮挡内容/焦点。
- **不得渲染价格字段或占位价格；价格不应从服务端传给组件。**

### 批量询盘清单
- 卡片/列表可勾选多个商品；已选数量始终可见；支持删除单项、清空、跨页保留。
- 点击询盘前显示将发送的 SKU 清单预览；每次最多 20 个 SKU（初始默认值）；所有选中 SKU 必须进入 WhatsApp 预填消息，超限不能默默截断。
- 弹窗说明将打开 WhatsApp/WhatsApp Web；不承诺系统能知道对方是否真正发送消息。

## 5. 后台页面规范（中英双语）

- 页面布局：侧栏导航 + 顶部面包屑/标题 + 操作区域 + 筛选区 + 数据区 + 分页。
- 表格每列可读、宽度合理；长文本截断并支持查看；操作列不堆叠过多按钮，次要操作放菜单。
- 创建/编辑使用一致的表单布局；必填星号、字段错误、帮助信息、提交中状态、成功/失败提示统一。
- 删除、停用、批量下架、导出文件删除等不可逆操作需确认，并显示目标对象和影响范围。
- 复杂表单按基本信息、规格、包装/箱规、分类/标签、图片、发布设置分组。
- 所有 UI 文案通过 `messages/zh-CN.json` 与 `messages/en-US.json`；键名稳定，例如 `products.fields.sku`，不可将中文作为逻辑分支条件。
- 后台日期时间按设置时区显示；表单提交传 ISO 时间；金额旁标明币种，尺寸/重量字段始终标明单位。

## 6. 组件标准

统一封装：Button、Input、Select、TreeSelect、DateTimePicker、DataTable、Pagination、StatusTag、ConfirmDialog、Drawer、Modal、Upload、ImageGallery、EmptyState、ErrorState、LoadingState、PermissionGate。

- TreeSelect 必须支持任意层级、搜索、已选路径展示、禁选规则和移动环检查的服务端校验。
- Upload 组件显示允许格式、尺寸限制、进度、失败原因、预览/移除；文件校验不能只在浏览器进行。
- DataTable 统一 loading/empty/error 状态、分页、排序、筛选回显、键盘可达性。
- 权限组件仅改善 UI，不替代 API 授权。

## 7. 无障碍与状态反馈

- 表单 Label 与输入关联；错误提示通过 aria-describedby 关联；键盘 Tab 顺序合理；弹窗管理焦点并支持 Escape（危险确认需符合具体 UX 规则）。
- 颜色不能是状态唯一表达；标签文字同时提供状态含义。
- 每个异步动作要有 loading、成功或失败反馈，避免重复点击。
- 遵循尊重用户偏好的 reduced motion；动画不影响数据可读性。

## 8. 禁止项

- 禁止各页面随机挑颜色、字号、圆角或临时创建不一致按钮。
- 禁止用 emoji 代替核心图标系统；禁止只做桌面布局再强行缩小到手机。
- 禁止用虚构统计数字/假客户数据作为已完成实现；开发样例必须明确标注 mock。
- 禁止价格字段进入前台页面，即便最终 CSS 不展示。
