# 01. 产品需求基线（PRD）

## 1. 项目定位

面向海外 B2B 买家的网站，展示公司产品与包装资料，引导访客通过 WhatsApp 联系销售，不在线展示产品报价或在线支付。前台界面使用英文；后台管理界面提供简体中文和英文切换。

## 2. 用户角色

- 访客：浏览首页、产品、品类、关于我们、联系我们、FAQ；选择产品后跳转 WhatsApp。
- 销售人员：由管理员创建账号后登录后台，录入或查询 WhatsApp 询盘客户。
- 产品运营：管理品类、商品、标签、精选/新品、广告、产品报价单模板。
- 管理员：管理用户、角色、菜单、权限、字典、全局配置与业务数据。
- 系统任务：处理 Excel 导出、PDF 转换、文件清理和访问数据聚合。

权限通过 RBAC 控制，具体页面和按钮权限不得只靠前端判断。

## 3. 后台功能范围

### 3.1 登录与账号
- 账号/密码登录；无公开注册入口。
- 用户由后台“用户管理”创建、禁用、重置密码、分配角色。
- 登录失败限流；多次失败触发暂时锁定/冷却；退出登录使 Session 失效。
- 初始化管理员通过 CLI/bootstrap 命令建立，首次登录强制改密。

### 3.2 菜单管理
- 菜单支持父子级、排序、路由、图标、显示状态、权限代码、外链标志。
- 菜单显示名称使用翻译资源 key 或按 locale 存储的翻译，当前简中/英文，扩展语言不改表结构。
- 菜单配置不是权限的唯一依据；API 仍独立执行权限校验。

### 3.3 角色与权限
- 权限颗粒度：查看列表、查看详情、创建、编辑、删除、导入、导出、发布/下架、下载文件等。
- 权限代码使用稳定机器码，如 `product.read`、`product.update`、`quote.export`。
- 角色授权到权限；用户可有多个角色。超级管理员权限不可由普通角色修改。
- 改权限后应在下一次 API 请求生效；如采用 Session 权限缓存，必须可主动失效。

### 3.4 用户管理
- 字段：登录账号、显示姓名、状态、角色、最近登录时间、创建/更新时间。
- 密码仅存哈希；密码不允许回显；管理员重置后生成一次性随机密码或强制用户首次改密。
- 禁止删除当前正在使用的最后一个有效超级管理员；停用用户立即阻止新请求。

### 3.5 字典管理
- 字典类型与字典项分层；字典项有 code、启用状态、排序和多语言 label。
- 系统关键字典可锁定，防止删除代码依赖项。
- 初始商品生命周期字典：`available`（可用）、`preorder`（预售）、`discontinued`（已停产）。
- 发布状态独立：`draft`（草稿）、`published`（已发布）、`unpublished`（已下架）。新品/精选是独立布尔标记，不应与生命周期或发布状态混用。

### 3.6 广告管理
- 广告位、标题、图片/桌面图/移动图、目标 URL、开始/结束时间、排序、启用状态、语言范围。
- 前台只展示当前时间生效且启用的广告；上传图片使用统一图片服务。
- 外链协议必须限制为 `https`（必要时允许 `mailto` / WhatsApp 配置链接），避免 `javascript:`。

### 3.7 全局设置
- 公司名称、Logo、联系邮箱、地址、社媒链接、WhatsApp 号码、默认语言、SEO 默认值、页脚内容、隐私/条款链接、上传限制、站点分析保留期等。
- 设置分组、类型、是否敏感、是否公开。秘密值只允许写入和显示“已配置”状态，不在 API 回显原值。
- WhatsApp 电话号码保存为国际格式纯数字，生成链接时使用 `https://wa.me/<号码>`。

### 3.8 多级品类目录
- 树形无限层级（业务上可设置最大深度，例如 8 层作为保护，不在代码中硬编码“三级目录”）。
- 字段：父级、稳定 code、slug、名称、描述、封面图、排序、启用、前台显示。
- 名称采用独立翻译表；当前后台可编辑中文和英文。
- 可将商品直接关联到任意层级品类。前台筛选某个品类时默认包含该节点及所有后代商品；需提供可解释的面包屑。
- 禁止将父节点移动到自己的后代下；删除有子节点或关联商品的品类时需要阻止或提供明确迁移方案。

### 3.9 商品管理
- 字段：商品编码（全局唯一 SKU）、英文名称、描述、内部基础价格（CNY，永不公开）、商品尺寸（长宽高，统一单位）、重量（g）、所属品类、包装方式、标签、箱规尺寸、箱规重量（kg）、箱规数量、图片列表、生命周期状态、发布状态、新品标记、精选标记、排序和 SEO 字段。
- 建议字段单位：商品长宽高在后台录入与前台展示统一为 cm；商品重量 g；外箱长宽高统一 cm；箱规毛重 kg；每箱数量为正整数。界面显式显示单位。
- 图片支持主图、排序、替代文本；标签支持后台新增，并在前台产品卡片标题角落显示适当标签。
- `draft` 不可被公开 API 返回；`unpublished` 也不返回；`published` 且生命周期不是 `discontinued` 时可公开。已停产产品默认不在目录显示；如业务需要可另行配置只读展示。
- 新品/精选只能在发布后展示在首页相应模块；无可用商品时首页优雅展示空状态。
- 商品价格只能在后台权限控制范围内读取；应避免价格包含在公共 GraphQL/REST DTO、页面 props、搜索索引或日志中。

### 3.10 报价单 Excel 导出管理
- 可上传/维护多个模板；模板包含名称、说明、文件、版本、状态和字段映射/占位符定义。
- 导出页面可选择品类节点、是否包含后代品类、商品状态/发布状态等筛选条件，再选择模板并预览导出数量。
- 导出商品范围、模板版本、操作人、时间、文件路径、筛选条件、数量和状态写入记录。
- 导出为异步任务，页面显示排队/处理中/成功/失败；成功后支持下载，权限控制下载。
- 删除记录时，用户明确确认后安排数据库记录和对象存储文件协同物理删除；物理文件删除失败时保留删除任务状态并重试，成功后才硬删除业务记录。审计记录可保留不含文件内容的操作元数据。

### 3.11 Excel 转 PDF
- 管理员上传受支持 Excel（MVP 默认 `.xlsx`，不执行宏；旧 `.xls` / `.xlsm` 默认拒绝，除非另行安全评估）。
- 校验文件大小、扩展名、MIME、签名；限时、限页、限制工作表数与行列数。
- 转换通过隔离 Worker + LibreOffice headless；不在 API 请求中同步阻塞。
- 完成后返回 PDF 下载；输入文件和输出文件按配置保留，达到保留期后清理。
- 错误提供可操作提示，不返回服务器绝对路径、堆栈或敏感内容。

### 3.12 PI（Proforma Invoice）制作
- 通过结构化表单生成 PI 草稿，再渲染到指定 Excel 模板；可预览、保存、复制、导出。
- 包含 PI 编号、日期、有效期、卖方/买方信息、收货人、商品行、数量、币种、单价、金额、总额、贸易条款、付款条款、交付周期、包装/运输说明、银行信息和备注。
- 金额、币种、汇率/报价价、舍入规则必须显式；商品主数据的 CNY 参考价格与 PI 行单价分离，避免自动转换造成报价错误。
- PI 编号由服务端生成且唯一；PI 保存后修改时保留版本/审计；已正式发出的 PI 不静默覆盖，应创建修订版本或副本。
- 用 Decimal 运算；服务端重新计算每行金额和总额，不信任前端传入合计。

### 3.13 WhatsApp 客户询盘管理
- 客户主档唯一识别字段为规范化电话（E.164）；客户可有多次询盘记录。
- 字段：客户电话、国家/地区、接待业务员姓名、接待业务员手机、接待时间、询问商品/SKU、备注、来源和关联历史记录。
- 页面必须提供醒目的客户电话搜索框；输入带国家码/空格/括号的号码时进行规范化和模糊辅助检索。
- 录入前按规范化电话查重；重复客户展示历史接待信息，不重复新建客户主档，但允许新增一次询盘活动。
- MVP 采用业务员人工登记。若要自动读取 WhatsApp 聊天，需要后续接入 WhatsApp Business Platform 官方 API/Webhook；普通 `wa.me` 链接不能自动回传个人 App 的聊天内容。

### 3.15 内容页面管理
- 后台维护 About Us、Contact Us、FAQ 等前台内容；支持英文与简体中文管理数据，前台第一阶段只输出英文。
- 页面支持草稿/发布、排序、SEO 标题/描述；富文本内容经过白名单清洗。FAQ 支持问题/答案、排序和启用状态。

### 3.14 访问分析看板
- 指标分清：PV（页面访问次数）、UV（去重访客估算）、实时活跃会话（如最近 5 分钟有心跳）、历史趋势、国家/地区聚合。
- 世界地图显示国家级聚合访问情况与时间范围，不在地图上伪装精确到街道的访客定位。
- 国家判断使用 IP GeoIP 数据或合规供应商；IP 仅在处理时使用，默认不长期保存原始 IP，使用随机会话 ID/截断或不可逆标识进行统计。
- 实时数据按 10–30 秒轮询或 WebSocket 更新；显示最后更新时间、采样/延迟说明、国家未知的数量。
- 访客分析必须纳入隐私声明、适用地区的 Cookie/追踪同意机制、保留策略和访问权限控制。

## 4. 前台页面

1. 首页：英文品牌介绍、广告横幅、品类入口、精选产品、新品、预售产品、CTA。
2. 产品目录：品类树/面包屑、全局搜索、筛选、排序、分页、响应式商品卡片。
3. 产品详情：英文名称/描述、SKU、商品尺寸与重量、包装、箱规、图片、标签；明确不显示价格；WhatsApp 询盘按钮。
4. 批量询盘清单：可从列表/详情多选商品，持久化在本地会话；显示已选数量、移除/清空；点击 WhatsApp 时将所有已选 SKU 编码写入预填消息。
5. About Us、Contact Us、FAQ；内容可由后台或配置管理。
6. SEO：英文 title/description、canonical、sitemap、robots、Open Graph；所有页面内容与 JSON-LD 不含内部价格。

## 5. 业务流程关键约束

- 前台 WhatsApp 内容建议：`Hello, I’m interested in these products: SKU-001, SKU-002. Please share details and quotation.` 只放 SKU（可附产品 URL），不包含内部价格。
- 使用 URL 编码生成 `https://wa.me/<business-number>?text=<encoded-message>`；号码使用国际格式，不含 `+`、空格、括号或连字符。
- 为保证所有 SKU 能带入消息，默认最多一次批量选择 20 个商品（可配置）；临近上限给出提示，不能静默丢掉 SKU。
- 访问统计的“实时访客”是系统定义的活跃会话数，默认心跳窗口 5 分钟，不等同于精确在线人数。
