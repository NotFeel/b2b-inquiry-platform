# UI 重设计执行方案：管理后台 + B2B 商品询盘前台

> 适用项目：B2B 产品目录与 WhatsApp 询盘网站。本文是 UI 重构执行基线，应与 `AGENTS.md`、`docs/06-admin-public-ui-standard.md` 一起作为 AI 编码约束。目标不是仅调整颜色，而是改善视觉层级、信息密度、商品展示和询盘转化。

## 1. 设计目标与非目标

### 目标

1. 后台统一成为专业 SaaS 管理界面：清晰导航、可扫描的数据表、可预期的 CRUD 操作、统一空态和错误态。
2. 前台统一成为专业 B2B 产品目录：商品图片优先、类目入口清楚、支持筛选/搜索/批量选择、WhatsApp 询盘始终容易找到。
3. PC、平板、手机共用设计 Token 和组件，不分别开发三套不一致页面。
4. 保留已有业务规则：前台不展示价格；商品详情只显示产品与包装信息；询盘按钮把已选商品编码带入 WhatsApp 预填消息。
5. 解决截图中可能属于数据/资源的问题，例如商品图片显示为灰色占位，而不仅是做视觉修饰。

### 非目标

- 不因 UI 改造擅自变更后端业务状态和权限规则。
- 不用虚构商品填补真实数据缺口。演示环境可以准备明确标记为 Demo 的种子数据，生产环境只能显示真实商品。
- 不在前台 DOM、API 响应、页面静态数据中输出价格字段。

## 2. 当前截图的问题诊断

### 2.1 后台截图

| 问题 | 具体表现 | 执行改法 |
|---|---|---|
| 导航过于扁平 | 20 个左右菜单全部挤在一列，没有业务分组，部分功能文字颜色太暗 | 改成 5 个业务分组；支持分组折叠、当前菜单高亮、侧栏收起；统一图标和中英文标题 |
| 品牌区没有应用结构 | 左上“运营总览”像页面标题，不像系统品牌区 | 顶部改为产品 Logo/系统名，下面显示当前空间或环境（如有） |
| 页面头部信息不足 | 只有“审计日志”标题，没有面包屑、说明、相关操作 | 增加 Breadcrumb、标题、辅助说明和右侧操作区 |
| 审计日志不可筛选 | 表格直接开始，找不到时间、操作者、事件类型等过滤条件 | 增加筛选工具栏，支持关键词、日期范围、操作类型、操作者和重置 |
| 机器字段可读性差 | `auth.login_succeeded`、UUID 等技术值占据主要视觉注意力 | Action 显示本地化人类可读名称，并保留技术 code；UUID 截断，提供复制和详情查看 |
| 表格缺少交互反馈 | 表头、数据行、操作能力层级不够清楚 | 固定表头可选、行 hover、合理列宽、复制按钮、详情抽屉、空/加载/失败状态 |
| 页面下半部空白明显 | 当前只有 9 条记录，表格后大块空白 | 不要为了填满屏幕而放大行高；改用页面内有层次的筛选区、轻量统计和表格。记录少时自然留白是合理的，不允许生成假日志 |

### 2.2 前台截图

| 问题 | 具体表现 | 执行改法 |
|---|---|---|
| 主容器偏窄 | 大屏下主要内容只占中间约 1100px，左右留白显得失衡 | 内容容器最大宽度调整为 1280px；页面左右内边距随断点变化 |
| Hero 右侧浪费 | 大块绿色区域只放左侧文字，右边没有产品视觉 | 采用 55/45 两栏布局；右侧展示真实产品图拼贴/精选产品画面，不要放与业务无关的装饰图 |
| 类目视觉太弱 | 仅有一个小卡片，用户不容易理解可浏览的品类 | 用 3–5 个主类目视觉卡片展示图/简洁图标、类目名、商品数量；没有图片时使用统一的类别插画或图标 |
| 商品图是空灰块 | 图片区域无产品图，只能看到图片名或灰底 | 检查图片 URL、存储权限、CORS、接口字段和 `next/image` 域名配置；缺图时使用统一设计的 fallback，不允许裸灰块 |
| 商品密度不合理 | 大屏上只显示两张卡，商品信息层级也弱 | 桌面 4 列、平板 2–3 列、手机 2 列（窄屏可 1 列）；加载真实分页数据。真实商品不足时显示实际数量并提供询盘 CTA，不能复制假商品 |
| 询盘动作不突出 | 有产品搜索与数量按钮，但没有贯穿页面的清楚询盘流程 | 卡片提供单品询盘动作；多选后显示底部/移动端固定询盘栏，明确显示已选数量与“Ask via WhatsApp” |
| Header 搜索控件局促 | 输入框占位文本视觉上拥挤、导航与搜索抢空间 | 桌面采用居中容器和弹性搜索宽度；低于 1024px 收起部分导航或改为搜索图标，移动端打开独立搜索面板 |

## 3. 统一设计系统（Design Tokens）

以下为初始值，先在 UI 包中统一定义，再按真实页面验收微调。禁止各页面临时定义一套新颜色或间距。

### 3.1 颜色

```css
:root {
  --color-primary: #0F766E;
  --color-primary-hover: #115E59;
  --color-primary-soft: #E6F4F1;
  --color-text: #17212B;
  --color-text-secondary: #64748B;
  --color-text-muted: #94A3B8;
  --color-page: #F5F7FA;
  --color-surface: #FFFFFF;
  --color-border: #E2E8F0;
  --color-border-strong: #CBD5E1;
  --color-success: #15803D;
  --color-warning: #B45309;
  --color-danger: #B91C1C;
  --color-info: #1D4ED8;
  --shadow-card: 0 1px 3px rgba(15, 23, 42, .06);
  --shadow-popover: 0 12px 32px rgba(15, 23, 42, .14);
}
```

品牌绿只用于主按钮、链接、选中态、关键标识与少量品牌区，不要大面积让每个模块都变成绿色。状态颜色要有文字，不得仅靠颜色辨识。

### 3.2 字体和间距

- 英文前台：优先 `Inter` / 系统 sans-serif；中文后台使用 `Inter, "Noto Sans SC", "Microsoft YaHei", sans-serif` 作为字体栈。
- 正文 14–16px；辅助信息 12–13px；后台页面 H1 为 24–28px/600；区块标题 18–20px/600。
- 间距基线：4、8、12、16、20、24、32、40、48px。页面主区块间距建议 28–40px，卡片内部 16–24px。
- 圆角：输入框/按钮 8px；卡片 12px；大 Hero 16–20px；不要每个元素都使用胶囊圆角。
- 按钮高度：桌面 40px，紧凑表格操作 32–36px；触屏点击目标至少 44×44px。
- 交互焦点必须有可见 focus ring；文本和背景满足 WCAG AA 对比度目标。

### 3.3 布局断点

统一使用：`sm=640px`、`md=768px`、`lg=1024px`、`xl=1280px`、`2xl=1536px`。容器建议：

```css
.container-app {
  width: min(100% - 32px, 1280px);
  margin-inline: auto;
}
@media (max-width: 767px) {
  .container-app { width: min(100% - 32px, 1280px); }
}
```

后台数据表可全宽使用内容区，不要为了统一容器而把表格强行限制在过窄的最大宽度。前台营销内容和产品网格使用 1280px 最大宽度。

## 4. 后台整体布局规范

### 4.1 App Shell

- 桌面左侧栏宽 248px；收起状态 72px。小于 1024px 默认收起；手机改为 Drawer，不把窄侧栏永久占住内容区域。
- 顶部栏高度 64px：左侧面包屑/当前模块，右侧语言切换、通知（若实际有）、用户菜单和退出登录。
- 内容区背景 `--color-page`，内容左右 padding 桌面 28px、平板 20px、手机 16px。
- 页面头部布局：左侧 `Breadcrumb + H1 + 一行说明`；右侧放主操作按钮。标题区与筛选区间隔 20–24px。
- 卡片统一白底、1px 边框、12px 圆角、轻阴影；主内容不能被包在过多嵌套卡片里。

### 4.2 菜单分组建议

1. **工作台 / Workspace**：运营总览。
2. **商品目录 / Catalog**：商品目录、商品管理、品类管理、标签管理。
3. **询盘与分析 / Leads & Analytics**：WhatsApp 客户、访问分析。
4. **报价与文件 / Quotes & Files**：报价模板、导出记录、形式发票 PI。
5. **内容管理 / Content**：广告管理、内容页面。
6. **系统管理 / Administration**：用户管理、角色权限、菜单管理、字典管理、全局设置、审计日志。

菜单显示文本通过 i18n key 驱动，中英文分别放在 locale 文件中。菜单是否展示由权限决定，但所有 API 仍需后端独立鉴权。分组标题非链接；当前路由对应菜单有背景、左侧色条/图标状态和明确文字对比度。

### 4.3 通用列表页模板

所有后台列表页遵循固定顺序：

1. Breadcrumb。
2. H1、说明文字、右上主操作（如“新增商品”）。
3. 可折叠筛选区：关键词、状态、日期或业务相关条件；搜索、重置按钮位置一致。
4. 列表摘要：总条数、当前筛选条件（有需要时显示）。
5. 数据表：表头、排序、行操作、分页、加载/空/错误状态。
6. 新增/编辑优先使用右侧 Drawer（字段较多时）或独立编辑页；危险操作使用二次确认对话框。

筛选值改变是否自动查询需全站统一。建议默认点击“搜索”才提交筛选，输入框 Enter 可搜索；重置后恢复第一页并重新获取数据。

## 5. 审计日志页面专项改造

### 5.1 页面结构

```text
Breadcrumb: System / Audit logs
审计日志                         [导出 CSV]（按权限显示）
查看管理员登录、权限变更与关键操作记录。

[今日事件] [登录失败] [密码/权限变更] [操作管理员数]  （可选，来自真实聚合数据）

[关键词 / requestId / entity ID] [操作者] [事件类型] [开始日期—结束日期] [搜索] [重置]

时间 | 操作者 | 操作事件 | 对象 | Request ID | 操作
... 数据行 ...
合计 N 条                                             每页 20 条  分页
```

统计卡只在后端能够提供真实聚合数据时显示；没有相应统计接口则先不显示，禁止前端计算出不准确的指标或用静态假数字填充空间。

### 5.2 建议表格字段与样式

- 时间：宽度 170–190px，统一展示时区或在 Tooltip 中说明时区。
- 操作者：宽度 140–180px，显示姓名/账号，未解析时显示明确的系统主体标签。
- 操作事件：宽度 220–260px。例：`auth.login_succeeded` 显示为“登录成功 / Login succeeded”，技术 code 放在辅助文本或详情中。
- 对象：宽度 240–300px；显示对象类型 + 短 ID，长 ID 使用单行省略，hover Tooltip，旁边提供复制按钮。
- Request ID：宽度 180–220px，短显示，支持复制和精确筛选。
- 操作：详情按钮，打开右侧详情 Drawer 展示完整 JSON（格式化且敏感字段脱敏）。
- 表头高度 44–48px；数据行高度 52–56px；单元格水平 padding 12–16px；hover 背景 `#F8FAFC`。
- 桌面表格可横向完整呈现；小屏表格容器横向滚动，同时固定首列/重要操作（仅在确有需要且测试过时使用），不要把 UUID 自动折成多行导致表格高度失控。
- 分页需要显示当前范围（例如 `1–20 of 126`），第一页/末页按钮状态正确；切换每页数时回到第一页。

### 5.3 审计日志交互

- 默认按创建时间倒序；操作事件和操作者支持组合筛选。
- 点击 requestId 复制；点击日志行/详情按钮打开 Drawer。
- Drawer 中至少展示：时间、时区、操作者、事件 code、显示名称、实体类型、实体 ID、requestId、来源 IP（如记录且有权限）、结果、脱敏后的附加详情。
- 长内容用复制按钮，不使用 `alert()`。复制失败时提供选中文本的回退方式。
- 空状态说明“没有符合条件的日志”，提供清除筛选；接口失败显示重试按钮。

## 6. 前台整体布局规范

### 6.1 Header

- 桌面头部高度 72px，内容最大宽度 1280px；左侧品牌 Logo/名称，中间导航 `Home / Products / Categories / About us / FAQ / Contact`，右侧搜索与询盘清单入口。
- 搜索框桌面宽度 260–360px，可伸缩；占位提示必须完整，右侧 Search 按钮与输入框组合为一个视觉组件。
- 若导航较多，优先缩减非核心导航间距，不要让搜索框挤到文字裁切。1024px 以下可将部分导航收进菜单；手机使用 Logo、搜索图标、询盘清单图标和汉堡菜单。
- 品牌名可配置，不保留 `Your Company` 默认占位文本进入生产环境。

### 6.2 首页顺序

1. Header。
2. Hero 主视觉。
3. Shop by category 主类目卡片。
4. Featured products 精选产品。
5. New arrivals 新品。
6. Pre-order / Coming soon 预售产品（有数据时显示）。
7. 询盘流程/企业采购价值说明，例如 `Choose products → Send your list → Get a quotation`。
8. About/Factory capabilities 简介和 WhatsApp CTA。
9. Footer：About us、Contact、FAQ、隐私政策和联系方式。

不要把所有内容都挤在第一屏，也不要只留一个孤立类目。各模块标题、副标题、查看更多链接使用统一样式。产品数量不足的模块可隐藏，避免出现空板块。

### 6.3 Hero 改造

- 内容容器最大宽度 1280px；桌面采用左 55% 文案、右 45% 商品视觉；最小高度约 300px，建议范围 300–380px，垂直居中。
- 背景可继续使用深绿到品牌绿的渐变，但降低大块纯色的压迫感。Hero 右侧必须使用真实且授权的产品图片、组合产品图或工厂产品陈列图。图片采用明确裁切比例和圆角，不要塞进大量浮动装饰。
- 标题建议 40–48px/700，最大宽度约 600px；平板 34px，手机 30–34px。副标题 16–18px，行高 1.5，控制在 2–3 行。
- 主 CTA：`Browse products`；次 CTA：`Ask for a quotation` 或 `How to inquire`。第二个 CTA 需要滚动到询盘说明或打开 WhatsApp，不能只做装饰。
- 建议文案：`Wholesale products, quoted for your project`；副文案强调可浏览产品、批量选择型号、通过 WhatsApp 获取报价，不承诺没有实现的交付/认证能力。
- 手机端改为单列，文案在上、视觉在下；Hero 高度自适应，按钮可全宽或并排（空间足够时）。

### 6.4 品类卡片

- 桌面主类目网格 4 列；平板 2–3 列；手机 2 列，极窄屏 1 列。
- 卡片统一采用图片/图标 + 类目名称 + 商品数量（有真实数据时）+ 箭头或 `Explore`。
- 主类目卡片高度 150–190px；图片区域建议占卡片高度 55–65%，使用统一的 `object-fit: cover` 或类别插画。
- 默认首页展示一级类目，不要把所有四级类目全部铺在首页。用户点击一级类目后，在产品页筛选栏展开子类目；导航树通过缩进、箭头和选中态表达层级。
- 无类目图时使用统一线性图标或同一风格的彩色插画；禁止混用表情符号、真实照片和不同风格图标。

### 6.5 产品列表页面

桌面布局：左侧 240–260px 筛选侧栏，右侧商品区域；小于 1024px 筛选改为 Drawer/顶部筛选按钮。

右侧产品区域头部依次为：面包屑、页面标题与说明、结果数量、排序（如 `Featured` / `Newest`）、网格密度（可选）。筛选项包括多级品类、商品标签、状态（仅公开可见状态）、关键词；不得暴露内部草稿或已停产等不应公开的商品。

产品网格：

```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 20px;
}
@media (max-width: 1199px) {
  .product-grid { grid-template-columns: repeat(3, minmax(0, 1fr)); gap: 16px; }
}
@media (max-width: 767px) {
  .product-grid { grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 12px; }
}
@media (max-width: 360px) {
  .product-grid { grid-template-columns: 1fr; }
}
```

产品卡片结构：

1. 图片（建议正方形 `aspect-ratio: 1 / 1`，背景统一为 `#F8FAFC`）。
2. 左上角标签：Featured、New、Pre-order 等；标签颜色与字典/国际化 key 映射，不直接使用后台中文值。
3. 多选框放图片左上或卡片标题前，选中态清晰且整卡不会因勾选而跳动。
4. 商品名最多 2 行；SKU 独立一行且便于复制；描述 2–3 行截断。
5. 次级信息只放关键规格/类目，不堆叠所有字段。
6. 底部轻量操作：`View details` 和 `Ask via WhatsApp`。窄屏可以将次操作放进详情页，但多选询盘必须始终可发现。
7. **任何情况下不显示价格、价格区间、价格占位符或可推导价格的字段。**

注意：CSS 网格改为 4 列不等于数据会自动变多。截图仅显示两件 Demo 商品，应先确认 API 返回数量与真实商品图片。如果生产数据就只有两件，就显示两件真实商品、提供“询问其他产品”入口，而不是伪造产品。

### 6.6 产品详情页面

- 桌面主区 2 列：左侧产品图片画廊（约 48%），右侧商品信息（约 52%）；下方为 Description、Specifications、Packaging、Shipping/carton information 等分区。
- 详情页顶部显示类目路径和 SKU；产品名称 28–36px，标签紧贴标题或图片角落；图片支持缩略图切换和放大。
- 右侧显示描述、尺寸、重量、包装方式、箱规尺寸、箱规重量、每箱数量、所属品类等已公开字段。
- 主操作是 `Ask about this product on WhatsApp`；次操作可为 `Add to inquiry list`。不得出现价格、加入购物车结算、支付或库存承诺等商城交易语义。
- 手机端图片在上，商品信息在下；底部固定询盘按钮必须避开 iOS 安全区和浏览器工具栏。

### 6.7 批量询盘流程

1. 用户勾选产品时，顶部询盘清单计数同步更新。
2. 至少选中一件时，显示固定询盘栏：`3 products selected`、`View list`、`Clear`、`Ask via WhatsApp`。
3. 进入询盘清单可以删除单项、清空列表、返回产品目录；刷新页面后是否保留选择应明确，建议使用 session/local storage 仅保存 SKU 和必要显示信息，不保存隐私信息。
4. WhatsApp 预填文本例如：

```text
Hello, I would like to inquire about the following products:
1. SKU: DEMO-1001 — Hex bolt M12
2. SKU: DEMO-1002 — Flat washer M12

Please share your quotation and MOQ details.
Source: https://example.com/products/...
```

5. 文本需使用 URL 编码，链接通过服务端配置的销售号码生成；禁止把电话号码写死在多个组件中。
6. 点击前可提示“WhatsApp will open in a new window/app”；未选产品时按钮禁用或引导选品。记录网站侧的点击事件可以做，但不能把点击 WhatsApp 当作“消息已发送”或“询盘已成功收到”。
7. 移动端使用 `window.location` 或新窗口的策略需按目标浏览器测试，确保不会被弹窗拦截；桌面端新开标签时考虑 `noopener`。

## 7. 图片与数据呈现问题排查清单

截图里产品图片灰块是阻塞正式上线的问题，应按以下顺序定位：

1. 检查商品 API 是否返回主图 URL，路径是否为空、过期或为内部局域网地址。
2. 直接在浏览器打开图片 URL，检查状态码、鉴权、CORS 和静态资源域名配置。
3. 检查上传服务是否成功保存文件、数据库保存的相对路径是否与 CDN/静态目录映射一致。
4. 若使用 Next.js Image，确认 remotePatterns/允许域名配置正确，且没有将宽高、fill、sizes 等属性组合错误。
5. 图片组件提供 `onError` fallback；fallback 应包含简洁的商品类别图形和 `Image unavailable`（可本地化），不要只渲染裸灰背景。
6. 列表图片提供固定宽高比以避免 CLS；图片 lazy-load，首屏 Hero 的 LCP 图片按优先级加载。
7. 管理后台上传时验证格式、大小、像素尺寸；文件名随机化，保留原始文件名到元数据中；限制 SVG 或对其做安全处理。

## 8. 国际化要求

- 前台首期默认英文；后台首期支持 `en` 与 `zh-CN`。
- 所有页面文案必须来自 `packages/i18n` 的 key/value 文件，组件中禁止硬编码大段中英文三元表达式。
- 菜单名、商品标签、状态名称、表格操作、表单校验提示、空状态、日期与分页文字都必须翻译。
- 数据库存稳定的 code/key，界面显示通过 locale 字典映射；新增第三种语言不得修改业务代码。
- 日期按管理员所设时区呈现，前台使用配置好的默认时区策略；数字和重量单位通过 locale 格式化。

建议结构：

```text
packages/i18n/
  messages/
    en.json
    zh-CN.json
  config.ts
```

## 11. 验收标准

### 后台

- [ ] 1440px 宽度下左侧导航、顶部操作和内容区无重叠；侧栏可折叠，当前菜单状态清晰。
- [ ] 审计日志可以按日期、操作者、事件类型和关键词筛选，重置后列表正确恢复。
- [ ] 长 Entity ID / Request ID 不撑坏布局，能够复制完整值并查看详情。
- [ ] 中英文切换覆盖导航、标题、按钮、表头、分页、空态、错误提示，不允许混杂硬编码语言。
- [ ] 角色无权限时后端返回 403/统一错误结构；不能通过直接调用接口绕过前端隐藏状态。

### 前台

- [ ] 1440px 下主容器约 1280px，产品网格最多 4 列；1024px、768px、390px 和 360px 均无横向页面溢出。
- [ ] 商品主图加载成功；图片失败时使用设计统一的 fallback，图片区域不塌陷。
- [ ] 产品列表可按类目、关键词分页查询，选中多个商品后计数准确。
- [ ] WhatsApp 链接使用正确销售号码，消息中包含所有已选 SKU 和可识别的商品名称。
- [ ] 网站页面源码、前台 API JSON、客户端缓存和结构化数据中都不存在价格信息。
- [ ] 没有商品或筛选无结果时显示明确空状态和清除筛选/询盘 CTA。
- [ ] 移动端批量询盘栏不遮挡最后一个商品或详情页关键内容，并适配安全区。

### 质量门禁

- [ ] Lint、TypeScript、单元测试、相关端到端测试通过。
- [ ] 不新增未经批准的依赖；共享组件修改时检查所有使用页面。
- [ ] 不使用假统计、假商品填充生产页面。
- [ ] PR/交付说明包含视觉变更截图、测试结果、未解决问题及回滚方式。

## 12. 推荐设计原则总结

后台应优先服务“高频操作和数据效率”，前台应优先服务“看清产品、找到产品、批量咨询”。颜色只能建立品牌识别，真正提升观感的是一致的间距、清晰的标题层级、真实的商品图片、合适的信息密度，以及完整的加载/空/错/成功交互。
