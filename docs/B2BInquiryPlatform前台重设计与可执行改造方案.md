# B2B Inquiry Platform 前台重设计与可执行改造方案

- 版本：v1.0
- 状态：待评审方案；不代表代码已修改或测试已通过
- 项目基线：`项目背景与需求.md`、`技术架构与设计决策.md`、`已确认问题与解决方案.md`
- 日期：2026-10-20

## 1. 项目定位

本项目服务于小型 B2B 店铺/工厂，不是大型商城。前台定位为：

> 年轻、可爱、轻量、有真实工厂背书的产品展示官网，以 WhatsApp 询盘为主要转化方式。

网站核心目标：
1. 展示产品、分类、图片、规格和包装信息。
2. 引导客户通过 WhatsApp 询问价格、MOQ、定制、包装和交期。
3. 通过工厂照片、视频、生产过程、证书和荣誉建立信任。
4. 让小团队通过现有后台维护产品和品牌内容。

### 必须遵守的项目约束

- 支持 `zh-CN`、`en-US`；URL locale 是页面语言来源，导航、面包屑、标题、表单、通知和内容语言必须一致。
- 产品不显示价格；公开 API 不得泄漏内部报价或敏感设置。
- 保留产品目录、详情、图库、规格、标签、品类树、发布状态、生命周期和批量询盘能力。
- 复用现有技术栈、API、数据模型、权限、审计和文件存储机制。
- 修改前检查 `AGENTS.md`、README、路由、API、Prisma schema/迁移、权限与测试；本文建议路由和字段需与实际仓库核对。
- 不把方案描述成已完成的代码，不在未实际运行测试时声称通过。

## 2. 视觉方向

推荐 **Pastel Pop + Cute Factory（马卡龙色彩 + 可爱工厂品牌）**。让真实产品图片成为视觉主角，配合温暖底色和少量柔和色彩；避免严肃的传统工业风，也避免过度卡通化、低对比度和大量装饰。

### 建议色板

| 用途 | 名称 | 色值 |
|---|---|---|
| 页面主背景 | Cream Vanilla | `#FFF8F1` |
| 品牌辅助色 | Candy Pink | `#F5B7CF` |
| 工厂/品质区块 | Mint Green | `#BDE9D0` |
| 新品/亮点 | Sunny Yellow | `#FFC96B` |
| 分类辅助色 | Lavender | `#C9C6FF` |
| 标题/正文 | Soft Charcoal | `#453B4A` |
| WhatsApp CTA | 清晰绿色 | 根据对比度测试确定 |

色值为建议初稿，不代表当前网页已使用。最终结合 Logo、真实产品图和对比度测试确认。

### 字体与组件基线

- 英文标题：Nunito 或相近圆润字体；正文：Inter 或系统无衬线字体。
- Hero 主标题：桌面约 40–52px，手机约 30–36px。
- 正文约 16px，行高约 1.6。
- 产品卡片圆角约 16–22px，轻边框或弱阴影。
- 按钮触控高度约 44–48px。
- 内容容器可从最大宽度 1200–1280px 开始验证。
- 动效轻微，并尊重 `prefers-reduced-motion`。
- 颜色不能作为唯一状态提示；文字和背景需有足够对比度。

### 首页区块顺序

1. Header：Logo、精简导航、WhatsApp 入口。
2. Hero：一句品牌主张、真实产品/品牌场景图、Explore Products 与 WhatsApp CTA。
3. Shop by Category：图片为主的分类入口，数据由后台品类生成。
4. Featured Products：少量精选产品，不显示价格。
5. Meet Our Factory：工厂视频封面或照片预览，进入工厂页。
6. Quality & Awards：真实、审核通过的品质或荣誉内容。
7. How to Inquire：简单说明选产品、发 WhatsApp、获取报价的流程。
8. Final CTA：产品咨询或定制。
9. Footer：联系方式、分类、品牌介绍、FAQ、隐私政策和社交媒体。

导航主项建议为 Home、Products、Our Factory、Quality & Awards、About Us、Contact 和 WhatsApp CTA。FAQ、Privacy 放页脚，手机端采用易用的折叠菜单/抽屉。

## 4. 各页面功能要求

### 首页
- Hero 文案短、图片突出，不使用大型商城式复杂营销横幅。
- 分类由后台动态维护，不把示例类别硬编码。
- 产品卡片显示主图、名称、SKU、简短介绍和询盘入口。
- 首页区块应优先复用现有内容管理能力，支持排序/显示状态/双语文案（若现有模型支持）。
- 加载、空数据、图片失败时显示合理状态，不显示假数据。

### 产品目录与分类
- 搜索、品类筛选、标签筛选和分页。
- 品类关系使用稳定 ID/`categoryId`，不用翻译名称作为关联键。
- 明确筛选是否包含子孙品类，分页总数需与筛选条件一致。
- 仅展示允许公开的已发布商品，不显示价格。
- 空结果有清晰提示和清除筛选入口。

### 产品详情
- 展示名称、SKU、图库、规格、材质/包装等已有字段。
- 支持主图/缩略图切换和图片失败降级。
- CTA：WhatsApp 单品询盘、Add to Inquiry。
- WhatsApp 消息带产品名称、SKU、产品 URL。
- 发布状态与生命周期分开，例如 `draft/published/unpublished` 和 `available/preorder/discontinued`。

### 询价清单
- 展示产品、SKU、缩略图、链接和数量；支持删除、改数量、清空。
- 顶部数量、卡片选中状态和底部浮动栏共享同一状态源。
- 重复添加有明确合并规则；空清单引导浏览产品。
- 产品下架或无效时提示移除；消息过长时提示拆分，不静默丢弃。
- 不要求注册；点击 WhatsApp 不等于消息已发送。

### Our Factory
- 工厂环境照片/视频、车间/设备/包装/团队照片。
- 生产流程按真实业务描述。
- 展示经核实的工厂介绍和能力。
- 视频使用封面后点击播放；首页不自动加载大视频。
- 页面末尾提供 Contact/WhatsApp CTA。

### Quality & Awards
- 证书、检测报告、奖项、展会记录、品质流程。
- 仅显示真实、有效且获准公开的内容；有效期/编号/验证链接只在真实可用时展示。
- 图片可查看清晰大图；无内容时隐藏入口或显示明确空状态，不伪造内容。

### About Us、Contact、FAQ、Privacy、404
- About Us：品牌故事、团队、发展历程和合作方式，不夸大规模。
- Contact：WhatsApp、邮箱、地址、社交媒体；可选表单需校验和防滥用。
- FAQ：仅写真实的 MOQ、样品、定制、交期、包装、运输和付款规则。
- Privacy：说明联系表单收集的信息、用途和处理方式，并按实际业务审核。
- 404：友好提示、返回首页和浏览产品，使用当前 locale。

## 5. 工厂媒体与后台内容管理

建议扩展现有后台内容管理，而不是另建 CMS。最终字段需以现有 schema 为准。

| 模块 | 建议维护内容 |
|---|---|
| 工厂媒体 | 标题、说明、图片/视频类型、媒体 URL/存储引用、封面、排序、启用状态、双语内容 |
| 视频 | URL、封面、说明、来源/授权信息 |
| 生产流程 | 步骤标题、描述、图片、排序、双语内容 |
| 证书/荣誉 | 名称、类型、颁发机构、图片、有效期（适用时）、排序、展示状态、双语说明 |
| 品牌故事 | 标题、正文、图片、发展历程、双语内容 |
| 首页区块 | 标题、简介、背景主题、排序、显示开关 |
| 全局设置 | Logo、品牌色、WhatsApp 号码、邮箱、地址、社交链接 |

### 文件与存储约束
- 上传校验 MIME、扩展名和大小，使用安全存储 key。
- 文件记录和对象存储是两个资源，不能假定数据库事务能回滚对象存储。
- 物理删除前检查权限、引用关系和主图状态；记录审计并支持对象存储删除失败重试/补偿。
- 不擅自删除所有历史版本或无关文件。
- 前台仅展示已启用且获准公开的内容。

## 6. WhatsApp 询盘流程

1. 用户浏览产品或分类。
2. 单品直接询盘，或多个产品加入询价清单。
3. 可填写数量和定制/包装等备注。
4. 系统根据真实数据生成英文消息。
5. 使用统一配置的号码构建 `wa.me` URL。
6. 打开 WhatsApp 并预填消息，由用户检查后主动发送。
7. 若需后台跟进，后端另行持久化询盘，不能只依赖浏览器本地清单。

示例消息：

```text
Hello! I'm interested in your products and would like to request a quotation.

1. Product: [Product Name]
   SKU: [SKU]
   Quantity: [Quantity]
   Link: [Product URL]

Could you please share your MOQ, customization options,
packaging details and lead time?

Thank you!
```

必须处理：
- 空清单不能生成空询盘。
- 同一产品重复添加有一致合并规则。
- 添加、取消、删除、清空和跨页返回后，数量与选中状态一致。
- WhatsApp 号码由全局设置统一管理并验证。
- 消息 URL 正确编码；消息过长提示拆分。
- WhatsApp 未安装时允许打开网页版。
- 无效/已下架产品提示移除。
- 记录点击不代表消息已发送。
- 公开 API 不得泄露内部报价或敏感设置。

## 7. 当前可见问题与处理方向

这些是此前页面可见信息和项目问题文档所支持的观察；根因仍需代码/API/数据库验证。

| 问题/风险 | 处理方案 | 优先级 |

| 可见 Demo 商品和占位图文案 | 替换真实数据和图片，增加发布前检查 | P0 |

## 8. 技术实施原则

### 开发前检查
1. `AGENTS.md`、README、项目文档和开发命令。
2. 前端框架、路由、共享 Layout、i18n 和样式机制。
3. 产品、品类、标签、媒体、内容、全局设置和询盘 API。
4. Prisma schema、迁移、唯一约束、外键和索引。
5. 图片/视频存储、上传和删除流程。
6. 权限 code、角色、菜单、审计日志和缓存机制。
7. 现有测试、启动命令和构建命令。
8. 当前首页和询盘流程可复现的问题。

### 分层与架构约束
- UI：页面、公共布局、产品卡片、图库、媒体展示和询盘组件。
- API/Route：输入校验、权限、HTTP 响应和统一错误。
- Service：业务规则、事务、关联检查、文件清理和审计。
- Persistence：复用现有数据库模型、外键、唯一约束和迁移。
- Storage：产品图、工厂媒体和证书文件。
- i18n：`zh-CN`、`en-US` 的 UI、菜单和内容翻译。
- Observability：审计、错误日志和合理的关键指标。
- 稳定关联用 UUID/code；菜单用于导航、权限 code 用于授权。
- 若已有 `MenuTranslation`，优先补齐翻译，不另建重复表。
- 多表变更用事务；外部文件操作设计补偿/重试。
- 敏感全局设置不通过普通列表 API 回传原文。
- 不因前台改造破坏现有后台商品、品类、标签、用户、角色、菜单、字典和设置功能。

## 9. 响应式与可访问性验收

### 测试视口
| 设备 | 宽度 |
|---|---:|
| 大屏桌面 | 1440px |
| 普通桌面 | 1280px |
| 平板横向 | 1024px |
| 平板竖向 | 768px |
| 常见手机 | 390px |
| 小屏手机 | 320–360px |

### 验收项目
- 无非预期水平溢出；产品卡片和 CTA 不被挤压。
- 导航可展开/收起，状态对辅助技术可感知。
- 浮动询价栏不遮挡内容，考虑移动端安全区。
- 输入框、按钮和图标控件有可访问名称。
- 复选框标签对应具体产品。
- Tab、Enter、Space、Escape 键盘操作合理，焦点明显。
- 图片 alt 有意义；装饰图不朗读冗余信息。
- 正文和按钮对比度经过验证。
- 尊重 `prefers-reduced-motion`。
- 加载、空、错误、无结果、无媒体和媒体失败状态均有反馈。

## 10. 实施阶段与验收标准

### P0：核心展示与询盘闭环
工作项：
1. 建立新视觉设计令牌和共享前台布局。
2. 重做首页 Hero、分类、精选产品、工厂预览和页脚。
3. 完善产品目录、分类详情、产品详情。
4. 修复询价状态同步与 WhatsApp 消息生成。
5. 清理 Demo 数据、占位图片和示例联系方式。
6. 修正主要 CTA 路由。

验收：
- 用户可从首页浏览产品、进入详情、添加产品并生成 WhatsApp 消息。
- 消息中的名称、SKU、链接和数量正确。
- 顶部数量、复选框和询价栏始终一致。
- 公开前台不显示价格/内部报价。
- 正式内容不出现明显 Demo、placeholder 或示例联系方式。

### P1：工厂与品牌信任内容
工作项：工厂页、品质与荣誉页、后台媒体/证书管理、About Us、Contact、FAQ 和中英文一致性。

验收：
- 授权用户可维护工厂照片/视频、流程、证书和荣誉。
- 前台只显示已启用且获准公开的内容。
- 文件上传、删除和排序遵守权限、引用检查、审计和存储生命周期规则。

### P2：发布质量
工作项：隐私政策、404、SEO、分享图片、响应式/可访问性回归、Demo 发布检查和关键指标。

验收：
- 代表性视口和核心异常状态完成测试。
- 测试报告记录实际命令、结果、失败项和未覆盖场景。
- 未完成事项与风险明确记录。

## 12. 风险与待确认事项

1. 品牌名称、Logo 和已有品牌色是否保留。
2. 实际产品类别、真实产品照片和视频素材。
3. 工厂环境、证书和荣誉是否有公开展示授权。
4. WhatsApp 正式号码、国家区号和消息语言。
5. 是否需要后台持久化正式询盘，还是当前阶段仅打开 WhatsApp。
6. 当前媒体上传与存储机制能否复用。
7. 已有页面路由与建议路由的差异。
8. 当前内容管理模型是否覆盖首页、工厂媒体和荣誉。
