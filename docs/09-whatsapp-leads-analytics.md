# 09. WhatsApp 询盘客户去重与网站访问看板

## 1. WhatsApp 询盘：先区分“链接点击”和“真实收到消息”

前台点击 `wa.me` 只能打开 WhatsApp 并预填一段文本，系统通常无法知道用户最后是否发送，也无法读取员工个人 WhatsApp App 中的对话。MVP 应将“网站询盘跳转意向”和“业务员实际接待记录”分开：前台可以记录 CTA 点击/意向（在隐私允许范围内），后台由接待业务员建立真实接待活动。后续若接入官方 WhatsApp Business Platform Webhook，才能按授权能力自动记录已接收消息。

## 2. 客户电话查重

### 录入步骤
1. 页面顶部固定客户电话搜索框；输入后调用 `GET /admin/customers?phone=` 或专用 lookup API。
2. 服务端规范化号码，优先解析 E.164；如国家码未知，要求业务员选择国家，不盲目猜测。
3. 如找到客户，显示客户主档、历史询盘时间、接待人、备注/关联 SKU；业务员可新增一次接待记录。
4. 如未找到，业务员填写客户国家、接待人姓名/手机、时间、产品 SKU 和备注，系统在保存时再次查重。
5. 数据库 `phone_e164` 唯一索引处理并发；若另一个业务员同时创建成功，当前操作应提示“客户已存在”并引导建立活动，不丢失输入数据。

### 关键字段
- Customer：`phone_e164`、国家/地区、客户备注、首次/最近联系时间。
- Inquiry Activity：客户关联、接待业务员账号（可选）、接待人姓名快照、接待人手机快照、接待时间、询问 SKU 列表快照、备注、来源（manual / whatsapp_webhook / website_click）。
- 客户主档与询盘活动分开，避免同一电话多次询盘覆盖旧记录。
- 客户数据为个人信息，按角色限制检索、导出和查看；默认不在普通请求日志中记录完整电话。

## 3. WhatsApp URL 与批量 SKU

示例预填消息：

`Hello, I’m interested in these products: SKU-001, SKU-002. Please share product details and a quotation.`

规则：
- WhatsApp 号码从后台全局设置读取，使用国际数字号码。
- 使用 `encodeURIComponent` 或等价 URL 编码；文本仅包含用户已选择产品的 SKU，必要时附上公开详情链接。
- 默认一次最多 20 个 SKU；限制可配置。选中超过限制时要求分批或提示调整，绝不静默截断。
- 不含内部价格、后台备注、客户数据库数据或未公开产品。
- 记录“点击 WhatsApp”事件不是“询盘已送达/已读/已报价”。UI 用准确措辞。

## 4. 网站分析事件定义

- `page_view`：每次页面有效浏览；用于 PV。
- `session_start`：产生匿名会话；在选定的会话窗口内用于估算 UV。
- `heartbeat`：前台页面定时发送；最近 5 分钟内有心跳视为 active session。
- `whatsapp_click`：点击 WhatsApp CTA；不代表对方发送消息。
- `product_select`：加入批量询盘清单（可选指标）。

会话 ID 应由安全随机数生成；不可将邮箱、电话或身份标识塞入分析 ID。服务端校验事件名称/路径/时间频率，限制每个 Session 的提交速率。

## 5. GeoIP 与世界地图

- 以国家/地区代码（ISO 3166-1 alpha-2）为聚合单位；国家显示访问次数和活跃会话数。
- IP GeoIP 只能推断大致地区，VPN、代理、移动运营商和企业网关可能导致误差；“未知”应是合法类别。
- 地图优先采用国家填色图或国家级聚合点，不画到用户具体住址；鼠标悬停展示国家、PV、活跃会话和最后更新时间。
- 筛选时间范围：实时、今天、过去 7 天、过去 30 天、自定义；明确时区和聚合粒度。
- 实时：每 10–30 秒刷新或使用 WebSocket；若采集/GeoIP 有延迟，显示最后更新时间。
- 历史：存储 page_views 原始事件时间范围可配置，超出保留期后聚合并清理原始数据。

## 6. 指标定义（避免误导）

- PV：页面浏览事件数。
- UV：按匿名会话/隐私友好标识估算的去重访客；不宣称等于真实自然人数量。
- 实时活跃会话：最近 5 分钟内至少一次合法心跳的会话数。
- 国家访问量：按 GeoIP 国家码聚合的 PV 或会话数；图表必须标记当前选择的指标。
- 不默认收集浏览器指纹；不因分析需要而无限期保存原始 IP 或精确定位。
