# 30. 移除 Excel 转 PDF，保留商品报价单 Excel 导出——AI 可执行实施方案

> 历史状态说明（2026-10-30）：本文记录当时的“下线 Excel 转 PDF”决策，历史内容
> 原样保留。业务方后续重新引入该功能，当前实现、限制、发布与回滚以
> `docs/38-admin-excel-to-pdf-conversion-implementation.md` 为准；本文不再代表当前功能状态。

> 文档版本：1.0  
> 目标仓库：`NotFeel/b2b-inquiry-platform`  
> 适用对象：AI 编码助手、前后端开发、测试、运维  
> 变更类型：定向功能下线 / 代码精简  
> 原则：小步修改、先审计再删代码、保留报价单 Excel 功能、不做无关重构。

---

## 1. 目标与范围

### 1.1 必须达成

1. **完整移除 Excel 转 PDF 功能**，包括用户入口、页面/表单、API 路由、DTO/schema、业务服务、队列任务、Worker 处理器、状态/错误码、专用配置、专用容器和依赖、测试、翻译文案及相关文档。
2. **保留商品报价单 Excel 导出**：保留现有导出入口、Excel 生成逻辑、模板管理、字段映射、授权校验、任务状态、文件存储、下载、导出记录及删除流程（以代码现状为准，不凭空新建重复功能）。
3. 保留 PI（Proforma Invoice）功能和 PI 的 Excel 模板/导出能力。只有实际代码证明 PI 必须经过 PDF 转换时，才调整 PI 工作流，并将“保留 PI 的 Excel 能力、不再产出 PDF”作为默认目标。
4. 清理不再使用的 PDF 转换依赖与基础设施，但不能误删其他功能仍在使用的通用文件、队列、对象存储、图片处理、Excel 处理依赖。
5. 完成自动化测试、静态检查、构建和功能验收，并更新架构图、README、部署文档、功能文档。

### 1.2 明确不做

- 不移除 Excel 导出商品报价单。
- 不移除 Excel 模板上传、预检、字段映射、模板版本或导出历史，除非代码审计确认某一独立子功能只服务于 PDF 转换且无其他调用。
- 不删除 PI、PI 明细、PI Excel 模板以及 PI 金额计算逻辑。
- 不修改无关商品、用户、角色权限、菜单、前台价格隔离、图片处理等业务。
- 不升级 Node、pnpm、Next.js、NestJS、Prisma 或其他核心依赖主版本。
- 不因本次代码精简执行破坏性数据库删除，不直接删除历史文件或业务记录。
- 不以“菜单隐藏”作为功能移除完成标准；后端入口与异步任务也必须被清理或安全下线。

## 3. 执行策略

采用以下顺序，不允许先大范围删除再寻找编译问题：

1. 建立变更分支和基线。
2. 全仓库定位 PDF 转换所有引用，绘制调用链。
3. 给每个引用标记为“仅 PDF”“报价单 Excel 共用”“PI 共用”“其他功能共用”“仅文档”。
4. 先删除 PDF 前端入口与后端业务链路；每一层修改后立即运行相关检查。
5. 再清除专用依赖、镜像、配置、任务调度、文档和过时测试。
6. 验证报价单 Excel 与 PI Excel 全链路。
7. 执行全量检查与部署验收。
8. 生成变更报告，列出已删功能、保留功能、依赖清理、测试结果和无法验证的项目。

## 4. 阶段 A：建立基线与保护工作区

在项目根目录执行：

```bash
git status --short
git branch --show-current
git log -1 --oneline
git switch -c refactor/remove-excel-to-pdf
```

执行要求：

- 如果工作区有未提交变更，先识别归属；不得覆盖或丢弃用户的改动。
- 若分支已存在，先检查分支内容，不要直接重置。
- 记录当前 main 提交 SHA 作为回滚参照。
- 初始审查阶段不修改数据库、不触发生产部署、不删除对象存储中的历史 PDF。

建立变更清单：

```bash
git grep -n -i -E 'excel.?to.?pdf|excel.*pdf|pdf.*excel|libreoffice|soffice|application/pdf|\.pdf|PDF转换|转PDF|PDF 转换' -- ':!pnpm-lock.yaml'
```

再检查锁文件与依赖配置：

```bash
git grep -n -i -E 'libreoffice|soffice|pdf-lib|puppeteer|playwright|pdfkit|jspdf|@react-pdf|exceljs|bullmq' -- '**/package.json' '**/Dockerfile*' '**/*compose*.yml' '**/*compose*.yaml' '**/*.yaml' '**/*.yml' '.env.example' 'pnpm-lock.yaml'
```

注意：`pdf-lib`、`puppeteer`、`playwright` 等名称本身并不能证明依赖只服务于 PDF 转换；必须跟踪实际 import/call site，禁止仅凭依赖名删除。浏览器测试也可能需要 Playwright。

## 5. 阶段 B：审计完整调用链

逐项检查以下位置；目录/文件名按实际仓库结构查找，不得假定每个路径一定存在。

### 5.1 前端（admin / storefront）

定位：

- Excel 转 PDF 菜单、按钮、卡片、操作列、表单和详情页面。
- 专用页面、组件、hooks、API client、请求/响应类型。
- 文件类型选择器、PDF 预览/下载链接、任务轮询/状态展示。
- `zh-CN`、`en-US` 文案与菜单 seed/翻译数据。
- 仅供 PDF 转换使用的 loading、错误码与状态枚举。

逐个确认引用。若页面把“Excel 报价单导出”与“Excel 转 PDF”合并为一页，**只移除转换区块和对应依赖**，不要删掉整个页面或共享表单/上传组件。

### 5.2 API 与业务服务

定位：

- Controller/route、DTO、Zod schema、参数校验、响应 contract。
- PDF 转换服务、转换器适配器、临时目录管理。
- PDF 专用 BullMQ queue name、job name、processor、worker、scheduler、retry policy。
- PDF 专用权限码、菜单 permission、审计事件和错误码。
- PDF 产物 MIME、扩展名处理、签名/页数校验和专用下载接口。
- 与 Excel 导出共用的权限、任务状态、对象存储、文件清理、审计和下载服务。

删除仅服务于 PDF 转换的代码。若 route/module 专用，直接移除；若混合在共享服务中，仅删除 PDF 相关方法和依赖注入项，并让报价单 Excel 继续编译与运行。

### 5.3 Worker / 队列 / 文件处理

检查：

- Worker 的启动入口、任务注册、队列注册、并发和关闭钩子。
- 专用 PDF worker 镜像、Dockerfile、compose service、Kubernetes Deployment/ConfigMap（若存在）。
- LibreOffice/soffice 执行命令、字体包、语言包、临时目录和资源限制。
- PDF 转换专用 Redis key、job 数据结构、job 状态、重试与失败清理逻辑。
- 共享的 Excel 生成、图片缩略图、物理文件删除和文件资产管理任务。

不要删除整个 Worker、Redis、BullMQ、对象存储、文件处理模块或共享临时文件工具，除非确认这些组件确实没有任何剩余调用方。若 Worker 只因 PDF 转换而存在，则先核实其 Excel 导出是否仍需异步执行；必要时保留 Worker 并移除 PDF processor。

### 5.4 依赖、环境和部署

审查：

- 根目录和各 workspace 的 `package.json`、`pnpm-lock.yaml`。
- Dockerfile、compose、部署脚本、Kubernetes manifests、CI workflow。
- `.env.example`、运行环境变量校验、配置模块与 README 部署说明。
- OS 包安装命令（apt/apk/yum）、字体、LibreOffice、PDF 工具程序。
- readiness/liveness 检查、日志告警、监控面板与 worker 数量说明。

移除规则：

1. 删除已确认只为 Excel→PDF 使用的 npm 包、系统包和环境变量。
2. 若相关库也用于 PI、网页打印、图片处理、浏览器测试或其他 PDF 功能，必须保留。
3. 修改依赖后使用当前固定的 pnpm 版本更新 lockfile，不能手工编辑锁文件。
4. 若生产镜像共享通用 Worker 基础镜像，只清理不需要的 PDF 软件包；不要改变运行用户、健康检查、时区、证书或其他业务运行条件。
5. 同步更新开发、测试与生产部署方式，防止代码不再调用 PDF、镜像却继续安装大型转换软件。

## 6. 阶段 C：实现删除与改造

### C1. 前端

- 删除 PDF 转换的导航入口、页面、按钮、菜单操作及专属文案。
- 如果页面混合两项功能，保留报价单 Excel 功能及其布局、表单校验和导出状态。
- 删除不再使用的 API client 方法、类型、hooks、轮询和专属组件。
- 如菜单记录来自数据库 seed 或 MenuTranslation，采用项目已有的幂等 seed/迁移机制处理，不要直接删除不确定是否被引用的菜单 ID。
- 不允许留下点击后报错的按钮、空白卡片、死链接、永不结束的 loading 或仅隐藏于 CSS 的旧入口。
- 后台仍遵循 `zh-CN` / `en-US` 国际化，移除不再使用的翻译 key；不得清除共享翻译 key。

### C2. API / Service

- 移除 PDF 专属 endpoint、Controller、DTO/schema、Service 方法和 module provider。
- 删除 PDF 专用权限代码及相关菜单绑定，前提是确认不影响其他权限链路与审计。
- 移除仅服务于转换的文件类型与 PDF 专用校验。
- 保留报价单 Excel API 的身份验证、权限检查、输入 DTO 校验、导出字段白名单、错误响应、审计与下载鉴权。
- 保留 PI 的业务逻辑、计算、数据快照和 Excel 输出。若 PI 当前 PDF 与 Excel 共用一个 endpoint/service，拆分输出格式分支，使 Excel 工作流可独立运行；默认禁用并删除 PDF 分支。
- 清除没有任何调用方的 PDF 专用类型、常量和错误码。共享常量不可盲目删除。
- 后端不得依赖前端隐藏入口确保功能下线；已移除的 API 必须不存在或返回正常的 404/路由不存在响应，不能继续执行后台转换。

### C3. 异步任务

- 移除 PDF 专用队列、job type、processor、worker 注册与 PDF 状态轮询。
- 清理仅用于 PDF 的重试、超时、取消、文件校验与临时产物清理代码。
- 保留报价单 Excel 导出队列（若现有实现采用队列），保证 worker 启动与任务完成流程完整。
- 如果历史队列中可能已有 PDF job，必须选择明确迁移方案：
  - 在发布前让旧 worker 将在途任务完成或取消；
  - 部署前暂停 PDF 新任务创建；
  - 对残留任务采用可观察的终止/失败策略，并记录日志；
  - 不允许删除整个共享 Redis 队列或清空共享 Redis DB；
  - 不需要保存历史队列 payload 中的敏感数据。
- 禁止新版本把历史 PDF job 静默识别成 Excel job。格式不同必须明确失败或标记为已取消。

### C4. 模板、导出记录和文件资源

- 保留商品报价单模板及模板版本。
- 保留 Excel 导出任务状态、下载权限、导出记录、删除确认与对象存储物理删除/重试。
- 保留 Excel 文件的正确 MIME：`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，并设置安全的 `Content-Disposition`。
- 不要把 PDF 文件记录错误地当成 Excel 文件记录返回。
- 历史 PDF 文件及数据库记录先保持不动。若产品决定彻底清除历史 PDF，另开迁移任务，先统计引用、确认保留期限、备份与审计需求，再做可重试物理删除；本次不做批量清除。

### C5. 依赖和构建配置

- 删除只服务 PDF 转换的 package 依赖与系统软件。
- 若移除依赖，执行包管理器命令更新 lockfile；检查 Docker 构建缓存和多阶段构建没有继续安装相关二进制。
- 清理 `.env.example` 中仅用于 PDF 的变量及对应运行时 schema。对通用文件配置不做删除。
- 如果某个 PDF 工具同时被其他功能使用，保留依赖，在交付报告中说明被保留的调用方和理由。

## 7. 报价单 Excel 必须保留的业务契约

请在实际代码中找到对应接口后，基于当前接口验证，不要擅自重新设计 endpoint。以下规则是验收要求，不是要求新增一份重复实现。

### 7.1 导出字段

商品报价单 Excel 的列应以现有模板/字段映射为准。至少审查并确认常见字段（若模型中存在）：SKU、英文商品名、产品尺寸、重量、包装方式、箱规尺寸、箱重、每箱数量，以及受授权控制的内部报价字段。

- 前台公开 API、HTML、SSR props、SEO/JSON-LD、公共缓存绝不能泄漏内部价格。
- 内部报价单 Excel 可在后台权限允许时包含内部价格。
- 导出商品集合由服务端查询并校验；如支持选择品类与包含后代，应去重并遵守状态/品类筛选。
- 单元格文本需要防公式注入：对不可信文本中的公式起始字符（例如 `=`、`+`、`-`、`@`）使用项目统一的安全处理方式；服务端生成的可信公式和用户文本必须区分。

### 7.2 权限与下载

- 未登录用户不能生成、查看历史记录或下载报价单。
- 导出与删除各自执行后端权限校验，不以隐藏按钮替代。
- 下载接口校验导出记录归属/权限和文件存在性；不可接受任意 object key 路径。
- 生成失败要返回稳定错误码和可理解提示；不泄漏服务器路径、堆栈、对象存储凭据。
- 删除记录与物理文件沿用当前可靠的幂等流程；对象存储删除失败时保留可重试信息，不假报成功。

### 7.3 文件完整性

- 生成 XLSX 后，使用现有库重新读取文件或执行适当完整性校验。
- 确认工作表名称、列头、数据行数、字段映射和数值格式正确。
- 检查文件名字符、编码和下载响应头。
- 生成文件不得写入 Git 源码目录；遵循现有对象存储/本地开发文件策略。

## 8. 数据库变更与历史兼容

本次首选只做代码/配置删除，不做 schema 删除。

执行前查找 Prisma schema、migration、枚举、数据表、Job 表、菜单权限和引用关系，判断哪些对象专属于 PDF：

- 如果没有 PDF 专属数据库对象：**不要创建空迁移**。
- 如果有 PDF 专属 enum 值/字段/表：先确认是否存有历史数据、是否被其他功能引用，再通过版本化 additive/兼容迁移和分阶段清理处理。
- 不可在同一发布中直接删除仍被生产旧版本使用的字段。
- 不要级联删除文件记录、PI、报价单、模板或审计数据。
- 对被共享的 `FileAsset`、`ExportJob`、队列记录与审计表，只移除 PDF 功能对它们的使用，不删除基础表。
- 提供回滚说明。代码回滚不保证已经取消/清理的任务会自动恢复，因此必须保留可观测性。

## 9. 测试要求

### 9.1 新增或更新的单元/集成测试

1. PDF 转换 service/controller/job 不再注册；不再有可用 API 入口。
2. 报价单 Excel service 正常生成 XLSX。
3. 选择 0 条商品、1 条商品、多条商品、商品名含中文/emoji/特殊字符时行为合理。
4. 字段映射、空字段、长文本、数值格式、SKU 前导零与公式注入防护正常。
5. 无权限用户不能导出、查看历史或下载；无删除权限用户不能删除。
6. XLSX 下载返回正确 Content-Type、文件名和状态码。
7. 导出记录与文件删除/失败重试没有因删除 PDF 模块而回归。
8. PI Excel 工作流仍能生成预期工作簿，金额计算和快照不受影响。
9. 菜单/翻译不再出现 Excel 转 PDF，但报价单导出入口依旧可见且符合权限规则。
10. 共享 Worker、Redis、BullMQ、对象存储、图片任务仍能正常启动/关闭。
11. 前台价格隔离测试继续通过。

## 12. 回滚策略

回滚触发条件：

- 商品报价单 Excel 无法生成/下载，或字段数据错误；
- PI Excel 退化；
- Worker 启动失败或共享任务处理异常；
- 生产出现权限、文件存储或导出历史问题。

回滚步骤：

1. 停止继续发布与清理任务。
2. 回滚应用镜像/Git 部署版本到记录的稳定 SHA。

6. 验证报价单 Excel 与 PI Excel 全链路。
7. 记录根因、影响范围和下一步修复项。
