## 0. 背景、目标与边界

报价计算器页面的商品、价格、双海运报价和订单级费用计算已经具备。本阶段新增的目标是：将计算器当前结果、已保存报价或已创建订单的数据，填入用户提供的 Excel 模板，生成可下载的客户报价单。

本功能是**报价计算器结果导出**，不是旧版商品筛选报价导出。必须保护 DOC-36 已有导出能力，不得改变其现有模板、商品筛选、加价计算或 API 行为。

### 0.1 三种导出来源

统一支持以下来源：

1. **当前计算结果**：导出当前计算器页面正在展示的有效计算结果，包含页面商品顺序和当前选择的 CBM/KG 运费方式。
2. **已保存报价**：按报价保存时的商品、价格、币种、汇率、费用及快照导出。
3. **已创建订单**：按订单创建时保存的商品、价格、币种、汇率、费用及快照导出。

三种来源最终转换为同一内部导出快照，再交给统一 Excel Workbook Builder。不得为三种来源复制三套 Excel 填充实现。

### 0.2 关键原则

- 服务端是金额、运费、权限和历史快照的可信来源。
- 当前计算器导出必须复用服务端现有计算逻辑，不信任浏览器提交的最终金额。
- 已保存报价和订单导出必须使用保存时快照，不得用当前 Product、Customer、汇率或字典内容覆盖历史值。
- Excel 图片必须真正嵌入工作簿，离线打开仍可显示。
- 生成文件不持久化到业务数据库或对象存储；本阶段以请求响应方式下载。
- 不新增重复的模板管理、文件存储或审计体系；先审查并复用现有基础设施。
- 不改变报价/订单原有计算、保存、转单和状态流转。

## 1. Excel 模板结构与填充规则

模板文件：`产品报价单模板.xlsx`  
工作表：`Quotation`

### 1.1 已确认模板结构

模板工作表为 A:G 七列，当前样例数据从第 7 行开始，汇总区域位于商品明细之后。

| 列 | 表头/字段 | 填充内容 |
|---|---|---|
| A | Product SKU | 商品 SKU |
| B | Product Image | 商品主图，作为图片嵌入单元格区域 |
| C | Product Name | 商品英文名称 |
| D | Material | 商品所属品类树最底层末端节点的英文名称 |
| E | Quantity (PCS) | 页面输入的商品总件数 |
| F | Unit Price([CURRENCY]) | 加价后的目标币种单件销售价格 |
| G | Total Price([CURRENCY]) | 商品总件数 × 目标币种单价 |

### 1.2 不填充区域

- 第 1～5 行保持模板原样，不填充业务数据、不重写样式、不删除 Logo。
- 第 6 行保持原有样式；F6、G6 的 `[CURRENCY]` 占位符由导出时的目标币种 code 替换。
- 不替换或重写第 1～5 行的任何内容。
- 模板中的 WPS `DISPIMG` 公式不是标准 Excel 图片嵌入方式，不得依赖或复制该公式实现商品图片。

### 1.3 动态商品行与汇总行

商品明细从第 7 行开始连续写入，汇总行紧随商品明细。

设商品数量为 N：

| 区域 | 行号 |
|---|---|
| 商品明细 | 第 7 行至第 6+N 行 |
| Product Subtotal | 第 7+N 行 |
| Shipping Cost | 第 8+N 行 |
| Total Cost | 第 9+N 行 |

示例：N=2 时商品为第 7、8 行，汇总为第 9、10、11 行。

- 不保留模板中的两条演示商品数据。
- 动态商品行沿用模板第 7 行的商品行样式，行高和边框等格式应保持一致。
- 汇总行沿用模板第 9～11 行的合并单元格、样式、对齐和数字格式。
- 根据实际商品数量更新工作表打印区域；避免多余空白样例行被打印或导出。
- 不得覆盖或破坏模板原有 Logo 和第 1～5 行合并单元格。

## 2. 商品数据与金额计算

### 2.1 字段来源

| Excel 字段 | 业务来源 | 规则 |
|---|---|---|
| SKU | 商品快照 | 使用本次计算或历史记录中的 SKU |
| Product Image | 商品主图快照/文件引用 | 取得图片二进制后嵌入 XLSX |
| Product Name | 商品英文名称快照 | 使用英文名称；历史记录不得读取当前名称覆盖 |
| Material | 末端品类节点英文名称快照 | 取商品所属品类树最底层末端节点的英文名称 |
| Quantity | 页面输入的商品总件数/历史明细数量 | 不以箱数、每箱数量或包装数量替代 |
| Unit price | 加价后的目标币种单件销售价格 | 每件单独向上舍入到两位小数 |
| Total Price | Quantity × Unit price | 使用已舍入的单价乘数量 |

### 2.2 单价计算

当前计算器来源：

1. 使用现有服务端计算器逻辑取得加价后的 CNY 商品销售单价。
2. 按当前报价目标币种汇率转换为目标币种未舍入单价。
3. 每件商品的目标币种单价单独向上舍入到两位小数（Decimal CEILING/ROUND_UP）。
4. Excel Unit price 写入该两位小数数值。
5. Total Price = 商品总件数 × 已舍入的 Unit price。

公式表达：

`unitPriceTarget = CEILING_2(unitSalePriceCny × exchangeRate)`

`itemTotalTarget = quantity × unitPriceTarget`

注意：必须先对每件商品单价舍入，再乘数量；不能先计算整行未舍入总额后才舍入，也不能对所有商品单价做平均舍入。

### 2.3 历史报价与订单

- 报价导出读取报价保存时的商品销售单价、目标币种、汇率和商品数量快照。
- 订单导出读取订单保存时的商品销售单价、目标币种、汇率和商品数量快照。
- 禁止因商品成本、加价比例、商品名称、SKU、币种汇率或商品状态后来发生变化而重新计算历史报价。
- 若历史记录未保存导出必需字段，必须明确返回“历史数据缺少导出所需快照”的业务错误，或在实施前设计经过审核的兼容补充方案；不得静默读取当前商品信息冒充历史快照。

## 3. 汇总金额

### 3.1 Product Subtotal

`Product Subtotal = Σ 每个商品行的 Total Price`

即汇总 Excel G 列所有商品总价。由于商品单价已逐商品舍入，汇总必须以导出的商品行金额为准，确保 Excel 明细加总与小计一致。

### 3.2 Shipping Cost

Shipping Cost 为订单级费用总和，包含：

- 当前页面选择的 CBM 或 KG 海运费（二选一，只计入被选中的报价）；
- 配送费；
- 其他订单级费用，例如包装、清关及其他已配置费用。

规则：

- 不得把 CBM 和 KG 两种海运报价相加。
- 不得将商品级海运分摊再次加到订单级 Shipping Cost，避免重复计算。
- 运费金额使用当前计算器页面所选运输方式对应的目标币种费用展示结果；应复用计算服务已有结果，不在 Excel Builder 中重新推导或二次换汇。
- 对报价和订单，使用保存时的费用及币种快照。
- 必须审查 DOC-39 实际保存的双报价、所选运输方式、汇率换算结果和费用快照字段，确认能准确还原页面所展示的 Shipping Cost。若历史快照缺失，不得自行用当前费率或当前汇率补算。

### 3.3 Total Cost

`Total Cost = Product Subtotal + Shipping Cost`

Excel 汇总金额使用与明细相同的目标币种数值，保留两位小数。服务端使用 Decimal 计算，禁止使用 JavaScript 浮点数直接累加金额。

### 3.4 币种表头约束与待澄清项

用户已确认只动态修改 F6、G6 的币种后缀。A9、A10、A11 汇总标签中原模板含有 `(CNY)`，按“只修改 F6/G6”的要求，本规范不擅自修改这些汇总标签。

**实施前需要产品确认是否允许将 A9、A10、A11 的币种后缀也同步改为目标币种。** 若保持原样，外币金额旁仍显示 CNY，存在标签与金额币种不一致的风险。开发不得自行忽略该冲突或扩大修改范围。

## 4. 三类数据源的统一快照

实现统一的导出数据结构，例如 `QuotationExcelExportSnapshot`。类型名称为建议名称，需遵循仓库实际命名规范。

建议快照至少包含：

- sourceType：current_calculation / quotation / order；
- sourceId（当前计算可为空）；
- templateId、templateVersion；
- currencyCode；
- exchangeRate（仅在当前快照或历史快照需要时提供）；
- items：按最终导出顺序排列的商品快照；
- selectedFreightMode：CBM 或 KG；
- selectedFreightAmountTarget；
- deliveryFeeTarget；
- otherFeesTarget；
- shippingCostTarget；
- productSubtotalTarget；
- totalCostTarget；
- 生成时间和 requestId。

每个商品快照至少包含 SKU、英文名称、末端品类英文名称、商品件数、目标币种单价、行总价和可读取的图片文件引用。

### 4.1 当前计算结果

- 服务端接收当前计算器所需输入，并调用现有计算服务重新校验、计算。
- 客户端传来的商品顺序必须保留。当前页面支持拖拽排序，导出顺序应与用户当前页面顺序一致。
- 可以提交商品 ID 的排序列表，但必须校验列表与计算请求中的商品集合一致，拒绝重复 ID、未知 ID 或缺失 ID。
- 商品名称、SKU、品类、图片和内部成本等权威数据由服务端读取；前端不能通过伪造字段覆盖。
- 导出必须使用页面当前选中的 CBM/KG 方式，不能默认选择或同时计入两种报价。

### 4.2 已保存报价

- 使用报价商品明细和保存时快照。
- 按报价保存时的商品顺序导出。
- 不重新读取当前 Product 成本、名称、SKU、品类或汇率作为历史值。
- 报价快照中没有图片或品类历史信息时，按历史数据缺失策略处理，不可静默伪造。

### 4.3 已创建订单

- 使用订单商品明细、订单费用和订单快照。
- 按订单创建时的商品顺序导出。
- 不读取当前商品主档、客户主档或最新字典翻译覆盖订单快照。
- 不允许订单后续状态或客户资料变更导致历史导出内容被改写。

### 4.4 历史图片与品类快照审计

DOC-39 的实施记录说明已保存商品、包装、价格、费用及计算快照，但尚不能仅凭文档确认每条历史记录都永久保存了末端品类英文名称和图片二进制/不可变文件版本。

开发前必须检查 Prisma schema、创建报价/订单的 snapshot builder、文件存储生命周期和已有历史数据：

1. 确认报价/订单快照是否保存末端品类 ID、英文名称及必要的 locale 信息。
2. 确认是否保存商品主图的稳定 FileAsset 引用，以及文件对象是否会被替换或删除。
3. 如果仅保存可变 Product/FileAsset 引用，不能承诺历史导出图片永远与保存时一致。
4. 如需新增历史快照字段或归档图片，先提出 additive migration / 对象存储保留方案并单独评审；不得在本导出功能中未经评审修改历史数据模型。
5. 对缺失历史数据给出明确错误或经产品批准的降级提示，不得把当前值冒充历史值。

## 5. Excel 图片嵌入

- 使用 ExcelJS 或仓库已采用的兼容库将图片二进制嵌入工作簿。
- 图片必须在下载后的 XLSX 文件内，不依赖浏览器登录态、CDN、R2 公网 URL 或网络访问。
- 优先读取已有 Storage Adapter / FileAsset 服务；不得在导出模块中硬编码 R2 endpoint、bucket 或凭据。
- 支持格式以仓库当前图片处理能力为准，至少验证 PNG/JPEG；不支持的格式应转换或返回明确错误。
- 图片按比例缩放，不拉伸、不裁切主体；放置在 B 列商品行区域内并居中。
- 动态商品行需设置足够行高；图片尺寸应受单元格边界约束。
- 不使用 WPS `DISPIMG` 公式。
- 不允许把图片 URL 写入单元格代替嵌入图片。
- 对缺失图片按统一产品规则处理：优先使用项目已有默认占位图；若没有占位图则留空并记录可观测告警，不应导致其他商品行错位。
- 必须设置单次导出图片数量、单张大小和总解压后工作簿大小限制。具体上限应先审查 DOC-36 与当前上传/文件策略，再确定，不把未经确认的数值写成产品承诺。

## 6. 模板、ExcelJS 与模块复用

开发前检查 DOC-36 的实现和当前代码，优先复用：

- 现有 QuoteTemplate / 模板文件管理能力；
- ExcelJS 依赖和工作簿处理工具；
- Storage Adapter / FileAsset 图片读取服务；
- RBAC 权限校验；
- AuditLog；
- 统一异常格式、下载响应封装和 i18n 规范。

但新模板的数据合同与旧版商品报价模板不同。必须确认模板类型、模板用途和校验器能否安全区分，避免新旧模板互相误选。

- 可以复用底层模板文件存储和模板管理服务。
- 如果现有模板类型不足以区分计算器报价模板，先审查 Prisma enum、模板校验器、管理 UI 和 seed，再决定是否新增独立类型/用途。
- 不得直接把旧模板类型 `product_quote` 用于新模板，除非审计证明其业务语义和校验规则完全兼容。
- 不新建第二套模板管理表或独立文件存储系统。

建议实现职责：

1. Source Resolver：识别当前计算、报价或订单来源。
2. Snapshot Builder：构建统一可信快照。
3. Template Resolver：读取启用的正确模板版本。
4. Workbook Builder：填充行、金额、图片、样式及打印区域。
5. Export Controller：执行权限校验并返回 XLSX 下载。
6. Audit：记录必要导出元数据，不记录敏感业务明细。

以上名称为逻辑职责，不要求机械创建同名文件或类。

## 7. API 设计建议

以下路径仅为候选方案，开发前必须审查现有 controller、route 和 API 命名约定，避免重复接口。

| 来源 | 候选接口 | 说明 |
|---|---|---|
| 当前计算结果 | `POST /api/v1/admin/quotation-calculator/export-excel` | 提交计算输入和商品顺序，服务端重新计算后导出 |
| 已保存报价 | `POST /api/v1/admin/quotations/:id/export-excel` | 根据报价快照导出 |
| 已创建订单 | `POST /api/v1/admin/orders/:id/export-excel` | 根据订单快照导出 |

响应要求：

- 成功：返回 XLSX 二进制流，设置正确的 MIME 类型和安全的 `Content-Disposition` 文件名。
- 文件名包含来源类型、业务编号或日期，不包含客户电话、邮箱等个人信息。
- 错误：沿用项目统一错误响应结构，返回可识别业务错误码。
- 不把图片二进制、成本明细或完整快照写入普通应用日志。
- 不将导出文件永久保存为订单附件，除非后续产品需求明确提出。

## 8. 权限与审计

### 8.1 权限

- 复用现有报价、订单读取权限和 RBAC 守卫。
- 是否新增独立导出权限，必须先检查现有 Permission code、角色授权 seed 和 DOC-36 权限设计。
- 当前计算导出至少要求有权执行报价计算，并满足服务端计算所需的成本读取权限。
- 报价导出要求有权读取对应报价；订单导出要求有权读取对应订单。
- 菜单隐藏或按钮隐藏不能代替服务端权限校验。
- 不得因新增导出接口扩大普通角色读取成本、客户信息或订单数据的权限。

### 8.2 审计日志

复用 AuditLog。建议记录：

- action；
- sourceType；
- sourceId（若存在）；
- templateId / templateVersion；
- 商品数量；
- currencyCode；
- selectedFreightMode；
- requestId；
- 导出成功或失败及错误类别；
- actorId、时间。

不得记录客户电话、邮箱、完整地址、商品成本、利润率、图片 bytes、对象存储凭据或私有 storageKey。

## 9. 前端交互

- 当前计算器：在计算结果区域提供“导出 Excel”操作；只有存在有效计算结果且计算未过期时可点击。
- 已保存报价详情：提供“导出 Excel”操作。
- 已创建订单详情：提供“导出 Excel”操作。
- 导出过程中显示 loading，防止重复提交。
- 成功时由浏览器下载文件；失败时显示项目统一双语错误提示。
- 对历史快照缺失、模板未配置、图片不可读取、权限不足等情况显示明确原因。
- 当前计算结果导出必须保持页面拖拽排序后的顺序。
- 按钮可见性遵循现有 RBAC/i18n 机制；服务端仍需独立校验。

## 10. 异常与边界条件

至少覆盖：

1. 未选择商品或商品列表为空。
2. 商品 ID 重复、缺失、无权限或已不可报价。
3. 商品数量为零、负数或超出允许精度。
4. 汇率无效、币种停用或服务端计算失败。
5. CBM/KG 费率无效或当前没有有效选中运输方式。
6. 费用快照缺失、重复计费或币种不一致。
7. 历史报价/订单缺少品类名称、图片引用或金额快照。
8. 模板不存在、模板停用、模板损坏或工作表名称不匹配。
9. 图片对象不存在、无权读取、格式不支持或超过容量限制。
10. ExcelJS 构建失败、内存不足、响应中断。
11. 用户无对应报价/订单读取权限或导出权限。
12. 同一用户连续点击导致重复请求。

失败必须返回明确错误，不得生成看似成功但内容不完整的 XLSX。对于单张图片缺失是否使用占位图，按第 5 节策略执行；不能让图片缺失导致商品行与金额错位。

## 11. 测试与验收标准

### 11.1 单元测试

- 单价换汇后逐商品向上舍入两位。
- 商品总价等于数量乘已舍入单价。
- Product Subtotal 等于所有商品行总价之和。
- Shipping Cost 只包含选中的 CBM/KG 海运费、配送费和其他订单级费用。
- CBM 与 KG 不会同时计入。
- Total Cost 等于 Product Subtotal + Shipping Cost。
- Decimal 精度正确，不使用浮点金额计算。
- 商品顺序保持输入顺序。

### 11.2 集成测试

- 当前计算结果导出。
- 已保存报价导出。
- 已创建订单导出。
- 报价/订单导出不会读取当前商品价格、名称或汇率覆盖历史快照。
- 历史图片和品类缺失时按定义返回错误/降级结果。
- 模板版本选择和停用模板处理。
- 图片真正嵌入 XLSX，解压工作簿可验证媒体资源存在。
- 权限不足返回 403，不能通过直接调用 API 绕过。
- 审计日志存在且不包含敏感字段。

### 11.3 Excel 文件验收

- 第 1～5 行和 Logo 保持不变。

## 14. 代码实现记录（2026-11-04）

- DOC-36 的 `product_quote` 导出路径保持不变。计算器模板使用独立的 `calculator_quote` 类型，复用 `QuoteTemplate`、私有 `FileAsset` 和现有 Storage Adapter；数据库中的模板用途为字符串，未新增 Prisma 列或 migration。
- 当前计算、报价草稿和订单导出均通过同一个 Workbook Builder。模板上传校验独立识别 `Quotation` 工作表、A:G 表头和连续三条汇总行；导出时再次读取并校验启用模板。
- 当前计算导出由服务端重跑现有 Decimal 计算，保留请求商品顺序；模板单价使用 CNY 销售单价乘当前汇率后逐商品向上舍入两位，行总价按已舍入单价乘件数并舍入两位。Shipping Cost 使用本次计算产生的目标币种费用行总和。
- 商品表头和 Product Subtotal、Shipping Cost、Total Cost 汇总标签中的 `[CURRENCY]` 在导出时统一替换成目标币种 code；解析器同时兼容旧模板中固定的三位币种后缀。现有产品报价模板的五处货币单位标记均使用 `[CURRENCY]`。
- 报价与订单快照新增 JSON 键：`categoryId`、`categoryLeafNameEn`、`categoryLocale`、`imageSnapshotStatus`、`imageSnapshotAssetId`。新记录要求有英文商品名与可唯一解析的末端英文品类；商品主图存在时复制到 `private/quotation-snapshots/` 并登记为私有 `FileAsset`。报价转订单会复用该快照引用。
- 商品原图的 `FileAsset` 必须是 `ready`、`product-image` 且 `isPublic=true`（代表获准用于公开商品展示）；`product-image/` 原图仍由 Storage Adapter 路由到私有存储。导出只在服务端读取该受管原图，再把历史副本写入 `isPublic=false` 的私有快照资产。
- 历史导出只使用报价/订单保存时的商品名、SKU、品类、图片引用、单价、汇率与费用金额。历史记录缺少商品/品类/图片状态或运费快照时返回 `QUOTATION_EXPORT_SNAPSHOT_MISSING`，不会读取当前商品或当前汇率补值。Shipping Cost 累加保存时 `amountForeign`，不重新推导运费。
- 图片归档对象在报价或订单明细 JSON 仍引用时保留；`cleanup-orphan-assets.ts` 已排除仍被这两类快照引用的对象。若历史业务记录删除，孤立资产由现有物理删除任务流程清理。
- 已按产品确认更新 A9:A11 的汇总币种后缀，使其与目标币种及 F6/G6 一致。
- API 与管理端 TypeScript 检查、相关 ESLint 检查通过。自动化测试和 Excel、WPS、LibreOffice 打开兼容性验收尚未执行。
