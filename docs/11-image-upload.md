# 11. 图片上传、存储与维护文档

## 1. 图片用途

- 产品主图/详情图
- 品类封面
- 首页广告/横幅（桌面和移动版可分图）
- Logo、公司介绍图片
- 其他后台内容媒体

所有上传统一走 File Asset 管理，业务记录引用文件 ID；不要在各业务表里自行拼接本地物理路径。

## 2. 推荐流程

1. 用户有 `file.upload` 与对应业务编辑权限。
2. 前端检查可接受格式并展示进度；服务端再次检查文件大小、签名、扩展名、MIME、图像可解码性和像素数。
3. 文件进入临时/隔离区；生成随机 storage key，拒绝路径穿越和覆盖已存在对象。
4. 对产品/广告图片创建派生规格，如缩略图、卡片图、详情图；保留必要原图，自动去除 EXIF/GPS 元数据。
5. 写入 File Asset 元数据：原始显示名、storage key、MIME、字节数、宽高、SHA-256、处理状态、上传人、创建时间。
6. 图片处理成功后绑定到产品/品类/广告；未绑定的临时资产按保留期清理。

## 3. 格式与限制（初始建议）

- 接受 JPEG、PNG、WebP；SVG 默认拒绝，除非提供严格消毒流程。
- 单张上限可设为 10 MB；最大像素尺寸/像素总量需配置，避免图片炸弹；具体限制在全局设置中维护并由服务端强制执行。
- 产品图推荐统一视觉比例，原图不强制裁切；派生图使用 `object-fit: contain` 或按设计决定的裁切模式。
- 保存 alt text；英文前台图片 alt 需要有意义，装饰图使用空 alt。
- 文件名显示时转义，不用其直接形成 URL 路径；物理 key 使用 UUID/随机串和受控扩展名。

## 4. 前台展示优化

- 使用合适尺寸的 responsive image 与 `srcset`，首页主视觉以外图片延迟加载。
- 主图设置合理宽高比/尺寸预留，减少布局跳动；避免将原始超大图直接作为所有列表缩略图。
- CDN 只缓存公开且已发布的派生图；后台私密附件、PI 和报价文件禁止进入公共缓存。
- 产品/品类更新图片后使相关 CDN/Next.js 缓存失效，避免旧图长期残留。

## 5. 删除、替换和引用

- 删除前查询所有引用；公共使用中的图片优先解除引用/替换，避免删除后出现断图。
- 默认逻辑删除资产记录并安排物理对象删除；如法规/合同要求硬删除，则按删除流程验证对象存储删除结果。
- 不得仅删数据库行而遗留物理对象，也不得只删对象而让数据库继续显示可用。
- 上传失败、图片处理失败和孤立文件要进入可检索的管理列表并可安全重试/清理。

## 6. 备份与维护

- 依据重要性配置 Bucket 版本与生命周期；注意“业务删除”与对象版本保留策略冲突。
- 定期检查孤立对象、引用缺失、哈希重复、过大图片和处理失败资产。
- 维护脚本默认 dry-run，输出将影响的数量；实际删除需显式 `--apply`，并留审计记录。
