# User Management Skill — 用户管理与角色分配

在处理后台用户管理、用户编辑、角色选择器、RBAC 分配、密码重置和用户状态变更时必须加载本技能。

## 强制要求

1. 先检查当前项目的 Users 页面、Users API、Roles API、权限代码和审计实现，优先复用，不得盲目创建平行模块或重复接口。
2. 角色选择只能使用服务端角色 API 返回的数据。禁止使用逗号分隔文本、自由输入角色 code 或仅靠客户端字符串映射分配角色。
3. 前端提交角色 `id` 数组；后端重新校验角色存在、可分配性与操作者授予权限。UI 的隐藏/禁用不能替代后端 Guard/Policy。
4. 创建和编辑共用表单及校验规则。编辑账号默认只读；显示姓名可编辑；角色分配按权限开放；状态和密码操作继续独立处理。
5. 用户与角色关联的替换操作必须事务化，并防止最后一名有效超级管理员被降权/停用。权限缓存或 Session 权限快照必须及时失效。
6. 加入创建、信息更新、角色变更、状态变更及密码重置的安全审计。审计与普通日志不得含密码、密码哈希、Cookie、Session token 或临时密码明文。
7. 多选下拉需覆盖 loading、error、empty、403、选项过期、提交中、字段验证、并发修改冲突与键盘操作。
8. 新建/编辑接口返回的对象必须使用字段白名单，不得直接序列化 ORM 用户实体。
9. 修改模型时提交版本化迁移；若现有 `AdminUser`、`Role`、`UserRole` 已满足需求，不做无必要的 schema 改动。
10. 提交前添加前端、后端和关键 E2E 测试，并提供已执行命令及真实结果。
